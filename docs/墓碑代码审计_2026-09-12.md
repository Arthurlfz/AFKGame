## A1. 空壳逻辑（最该删，有误导性）

### `boostEarlyDropRate()` — `docs/js/ui-fixes.js:257-275`，调用点 `ui-fixes.js:287`

注释与函数名声称「提高新手期(Lv1-6地图)装备掉率 / 确保新手前 10 场必掉一件白装」，**实际一行都没实现**：

```js
window.Drop.roll = function () {
  const result = origRoll.apply(this, arguments);
  try {
    const area = ...; const fightCount = ...;
    if (fightCount < 10 && !result.equip) {
      // 前10场没掉装备时，补一个白装   ← 只有注释，没有代码
    }
  } catch (e) {}
  return result;   // 原样透传
};
```

危害：它 **hook 了核心掉落函数 `Drop.roll`**，每场战斗掉落都多走一层包装 + try/catch，
却零效果；更糟的是名字会让人误以为「新手保底掉装」已经做了。
删掉后掉落结果 **完全不变**（`result` 原样返回）。

## D. 看着像孤儿、其实不能删

- `docs/js/core/pet-sprites.js`：**没被 `游戏.html` 加载**（PetSprites 已内联进 HTML，见 `游戏.html:831-833`）。
  但它是内联副本的**源文件**，`docs/tests/vtest_sprites_coverage.js` 断言「HTML 内联副本与 pet-sprites.js 同步」。删了测试会红。
- `docs/js/core/build-sim-global.js`：构建脚本（`node build-sim-global.js`），由 `battle-sim.mjs` 生成 `battle-sim.global.js`。不是运行时代码。

## E. 不建议按「未引用」清理的部分

- **`core/config.js` 数值**：多处靠动态键名读取（`Config[k]`、模板拼 key），静态引用计数不可靠，误删会直接改数值。**别用引用计数清 config**。
- `console.log(_m)`（`core/battle.js:509`）：是有意诊断埋点，写 `window.__battleLog`，排障靠它。
- 空 `catch (e) {}`（`main.js:617`、`ui-market.js:57`）：包的是 `localStorage`，隐私模式会抛，正常防御。
- `p.then(function(){}, function(){})`（`pet/pet.js:89,92,108`）：fire-and-forget，不是墓碑（但会吞 reject，属隐患非墓碑）。

### ⏸️ B 级 CSS：已定位 134 个死块，但暂缓执行
- 修正了「动态拼接类名」误判后，确认识别出 134 个 CSS 死块（最初扫描 180 个类，排除 148 个有拼接前缀的动态类如 `fs-item--*`/`q-*`/`quest-list-item--*`）。
- **暂缓原因（遵守「确定不影响」硬要求）**：实测发现项目存在「CSS 类名 ≠ JS 实际类名」现象——`ui-capital.js:112` 建筑元素用的是 `.cap-bldg`，而 CSS 里写的是 `.capital-building`（命令行 grep 全仓确认这些类仅在 CSS 出现）。这说明纯静态「零出现=死类」在本案**不完全成立**，且这些死块全是核心 UI 类（背包 `bag-card`、市场 `market-item`、任务 `quest-panel-*`、打造 `craft-stone-*`、主城 `capital-building`、设计系统 `fs-*`/`btn-primary`），一旦误删真实活类视觉破损严重；而 CSS 删除无法靠 node 测试验证（`@media` 嵌套块也不透明）。
- **安全路径**：用浏览器运行时采集真实 DOM 类名集合，与 CSS 定义对比，精确确认哪些类真死后再删（或逐文件视觉回归 + `.bak` 备份）。完整待删清单见上文 B 级。
