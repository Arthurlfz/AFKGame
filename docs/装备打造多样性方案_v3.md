# 装备打造系统 · 通货与词缀多样性（修订版 v3）

> 依据反馈修订：通货按"只加随机剥离石"收敛；词缀改为"非乘算膨胀"的新模型根除数值灾难。
> 已作废方案：v1 的 攻速/格挡/反伤、v2 的 蜕变石/洗练石、以及一切"定向选词缀"设计。

## 一、现状（已核实）

- 属性公式（《游戏设计理念》§5.2）：`最终 = 基础值 + 等级 × 成长值 × 系数`（hp/atk/def 皆然；速度走 `speeds` 表）。
- 装备词缀当前为 **百分比乘算**：`最终属性 = (基础+等级×成长×系数) × (1 + Σ词缀%)`。
- 问题：成长值×等级在高等级/高成长时已被放大到很大；再叠加百分比词缀 → 数值 runaway，后期崩坏。现有 6 条 % 词缀已隐含此风险。

## 二、词缀模型（核心修订：换计算公式）

目标：保留"百分比词缀"的构筑感，但**不让装备加成随等级/成长二次膨胀**。

### 候选 A（推荐·软封顶乘算）
```
最终 = (基础 + 等级 × 成长 × 系数) × (1 + 有效% )
有效% = Σ词缀% ≤ CAP → 直接采用
        > CAP   → CAP + (Σ词缀% − CAP) × 0.3   // 超出部分仅 30% 生效
```
- CAP 建议 60%~80%（即单件满 roll 最多约 +80%~+110%）。
- 改动极小：只在 `getEquipBonuses`/结算处对 `pct` 求和后套一层封顶。
- 保留"% 手感"与 T 阶分级，只是上了天花板。

### 候选 B（锚定基底·加算）
```
最终 = (基础 + 等级 × 成长 × 系数) + 基础 × Σ词缀%
```
- 词缀只作用于"基底"，不乘 等级×成长。
- 装备在前期有效、后期靠成长，构筑身份感（暴击/穿透/吸血类型）仍在，但数值不膨胀。
- 代价：高等级时装备绝对数值占比下降。

### 候选 C（按词条独立封顶）
每条词缀各自封顶（如单条最多 +30%），超出值作废；多条叠加仍可能逼近上限。
- 比全局封顶更细，但多条同类仍会堆满。

> 推荐 **A**：实现成本最低、保留%"涨（红）/跌（绿）"的本地惯例展示，且能直接解决 runaway。若你更想要"装备不喧宾夺主"，选 B。

## 三、通货（最终方案：只加随机剥离石）

保留原 4 种（强化/祝福/神圣/,增缀）；新增 **随机剥离石**：

| 通货 | 机制 | 说明 |
|---|---|---|
| 随机剥离石（新增） | 随机移除装备 **1 条**词缀（不指定哪条），消耗 1 颗 | 给"洗掉废条 → 增缀补回"的随机循环，守住寻宝内核 |
| 强化石 | 随机 1 条非 T1 词缀 T 阶 +1 | 现状 |
| 祝福石 | 随机替换 1 条词缀类型 | 现状 |
| 神圣石 | 重 Roll 全部词缀数值（保留类型/T） | 现状 |
| 增缀石 | 前缀优先新增 1 条随机词缀 | 现状 |

> 锁定石 / 蜕变石 / 洗练石 均移除：前者涉及"定向"，后者会随机抹掉已得好词条、且不如剥离干净。

## 四、词缀种类（适配挂机，沿用 % 模型）

保留：攻击%/生命%/防御%/速度%/暴击率%/吸血%。
可选新增（战斗向，避开 exp%/掉率% 这类冲击进度与经济的词条）：暴击伤害% / 穿透%。
> 若采用候选 B，新增词缀可放开；若采用 A，仍受全局封顶约束，安全。

## 五、落地改动清单

1. `config.js`：新增 `craft.strip`（随机剥离石），新增 `equipment.affixPctCap`（候选 A）。
2. `equipment.js`：AFFIX_POOL 若加新词缀则补条目。
3. `pet.js` / `battle.js`：`getStats` 结算处实现封顶或锚定（按选定模型）。
4. `equipment_craft.js`：新增 `strip(eq)`（随机删一条）。
5. `ui-craft.js`：新增"剥离"按钮 + 结果展示。
6. 测试：`vtest_affix.js` / `vtest_augment.js` 同步词缀池（如有新增）。

## 六、已确认公式（2026-09-01）

用户确认采用「等级底座放大、成长增量不参与」模型：
```
底座   = 基础值 + 等级 × 系数
成长量 = 等级 × (成长值 − 1) × 系数
最终   = 底座 × (1 + Σ词缀%) + 成长量 + 装备固定值
```

- 攻击% / 生命% / 防御% 只放大底座；成长值提供的额外属性不再被装备百分比二次放大。
- 已落地于 `docs/js/pet/pet.js` 的 `Pet.getStats`；装备基底和固定值词缀照旧直接相加。
