# 服务端权威施工图 v1（2026-09-23）

> **目标**：把「打造 / 进化 / 合成 / 涅槃 / 市集定价 / 副本」六处的数值结算从玩家浏览器搬到服务端。
> **为什么必须做**：现在这些数值都在客户端算完再写库，开脚本的人能直接改结果（改成长、改词缀、伪造副本层数），推广即被拆。
> ⛔ **未开工** —— 本文档是施工图，**动数据库之前必须先拿到用户授权**（宪法：动库串行、一次一个）。

---

## 0. 现状（一句话）

**野图挂机已搬完**：`core/idle-bridge.js` → EF `battle-settle`（已部署），服务端算完入账、客户端只回放录像。
**其余六处仍是客户端权威**：客户端算 → 客户端写 REST / 调只有"扣材料"能力的 RPC。
**服务端现成能力**：`spend_materials`（原子多扣）、`add_material`、`battle_settle`（事务化发奖样板）、
`check_god_synth` / `check_nirvana`（只读校验）、`_shared/` 六个共享模块（含 `equip-gen-server.mjs` 装备生成）。

## 1. 通用切法（六处共用，照 `resource-trial` 四步式）

```
① 幂等占位行（唯一键 run_id，撞 23505 → 直接返回上次结果，重复点击/重发无害）
② 服务端校验资格 + 原子扣消耗（spend_materials）
③ 服务端重算数值（纯函数，从前端抽到 _shared/*.mjs，与前端同源）
④ 服务端原子写结果（update pets / insert pets / delete pets / 写物品）→ 返回"已入账的结果"
```

客户端收到后**只做回放**（和 `idle-bridge` 一个姿势）：本地发奖/数值写入一律降级为 `dry`，
否则就是静默双倍收益（红线 5）。

**改宠物类操作（进化 / 合成 / 涅槃）必须沿用 `IdleBridge.duringPetEdit`** —— 托管挂机期间本地那份是演出预演值，
直接写回会把真账改小（红线 7）。

**共享数值的同步**：`_shared/config-server.mjs` 由 `gen_server_config.js` 从前端 config 生成，
`vtest_server_config_sync.js` 守一致性；打造还要用 `equip-gen-server.mjs`（`vtest_equip_gen` 守）。

## 2. 六处逐个

### ① 打造（craft）—— `js/equipment/equipment_craft.js`
- 现状：本地摇词缀（`applyCraft` L53：条数/类型/T 阶/数值/锁定石附加消耗）→ 本地改 → 并行两路写云端
  （`spend_material` + `equip_items.update`），**无事务**，失败靠本地回滚 + 0 行校验重试。
  魂铸 `soulCast` L321 单独出口，末尾 `deletePet` 失败只 warn（幽灵宠）。
- 服务端要重算：词缀条数 / 类型 / T 阶 / 数值 / 稀有度回写 / 锁定石消耗 / 魂铸的特质选取与升档。
- 新建：EF `craft-settle`（或并进一个 `pet-settle`）+ `_shared/craft-core.mjs`。
- 风险：装备生成必须与前端同源（`equip-gen-server.mjs` 已是范例）；魂铸的删宠要放到"写词缀成功之后"。

### ② 进化（evolve）—— `js/pet/pet_evolve.js`
- 现状：先原子扣素材（`spend_materials`）→ 本地算成长加成（随机区间 × 道具倍率）→ `updatePet` 写
  name/growth/evolve_times/evolve_stage；失败逐样退还（有窗口期丢材料）。
- 服务端要重算：成长加成、新名字/形态、进化次数、阶段。
- 新建：并进 `pet-settle` EF（动作 `evolve`）。
- 风险：最简单的一处，建议当**第一个练手**（扣→算→写→回放，全链路最短）。

### ③ 合成（synthesize）—— `js/pet/pet_merge.js`
- 现状：先原子扣 → **扣完之后**才调 `check_god_synth` 校验神级资格（L401-413，⚠️ 被拒时材料已扣未退）
  → 本地摇神级 / 变异 / 新成长 / 特质继承 → `savePet` 建档 → 建档失败整单回滚 → 删主宠 → 删副宠。
- 服务端要重算：神级概率骰、变异骰、新成长（四段加成）、特质继承（升档/降档/挤位）、名字与基础值。
- 新建：并进 `pet-settle` EF（动作 `synth`）；校验必须挪到扣款**之前**。
- 风险：数值骰最多最肥；"先建档后删素材"的铁律要保（红线 3）。

### ④ 涅槃（nirvana）—— `js/pet/pet_merge.js`
- 现状：`check_nirvana` 校验 → 原子扣 → 本地 snapshot → 改主宠 → `updatePet` 主宠（可逆）
  → `deletePet` 副宠（不可逆）→ 任一步失败走补偿链（删副宠失败还要反向 updatePet 写回旧值）。
- 服务端要重算：吸收成长（含阻尼/道具倍率）、特质植入（30% / 锁魂玉定向 100%）、
  `evolveTimes=0`、等级经验重置、`rebornCount+1`。
- 新建：并进 `pet-settle` EF（动作 `nirvana`）。
- 风险：唯一有"不可逆删除"的一处；服务端化后补偿链可以整段删掉（一次事务搞定）。

### ⑤ 市集定价（market pricing）—— `js/core/market.js` + `js/ui/ui-market.js`
- 现状：**上架价 = 玩家手填 `material_qty`，服务端零校验**（`supabase.js` L247/303 直接 insert）；
  税在成交 RPC 内算（与 `market.js:calcTax` 两份实现，靠注释同步）。
- 服务端要做：上架时校验价格上下限/税率单一事实源（不必把定价本身搬服务端 —— **玩家定价是玩法，不是数值结算**）。
- 新建：最小改动 = 给三张挂单表的 insert 加 RLS/CHECK 或改走 `list_*` RPC（蛋/材料已经是 RPC 了，照抄）。
- 风险：改动面最小，但**会动到 RLS** ⇒ 单独一批、串行。

### ⑥ 副本（trial）—— `js/trial/*`
- 现状：完全不走云端（资格在 localStorage，层数/成败全本地），**EF `resource-trial` 已部署但零调用**。
- 服务端要重算：层等级/难度/敌人属性、层奖励档位、每日资格、门票消耗、发奖。
- ✅ **前置已办（2026-09-23）**：`resource_trial_runs` 表已在线上建好（幂等，4 条 RLS 策略齐）。
- 🔴 **2026-09-23 接线前发现的漂移（重要，别当"只差接线"）**：
  服务端 `_shared/trial-core.mjs` 还是 **2026-09-09 的老模型** ——
  `planTrial` 读 `cfg.rounds`（现在 config 里只有 `floors:20`）⇒ 默认只有 **5 轮**；
  奖励 `rewardFor` 是老的「涅槃丹 / 重铸石 / 区域材料」老口径，**与现在的 20 层 `floorTiers` 档位完全对不上**；
  伤害是"按最大血固定比例"简化模型，不是真实的回合制战斗。
  ⇒ **照现状直接接线 = 服务端算出来的奖励和层数全是错的**。幸好 EF 零调用，没有玩家受影响。
- ✅ **已落地（2026-09-23）**：
  1. `_shared/trial-core.mjs` 已重写成 20 层同源（逐层 `simulateFight` + 血量跨层累计 + floorTiers 奖励），
     `vtest_trial_core.js` 守"与客户端逐层同源"。
  2. 双份 `battle-sim.mjs` 已加**显式敌人数值入口**（`enemyData.explicit`），`vtest_sim_sync` 仍 17 函数全等。
  3. 客户端已接线（开关 `Config.resourceTrials.serverAuthority`，默认开）：`js/trial/trial-server.js` 调 EF，
     演出走**公共播放器** `js/ui/battle/show.js`（摆人 / 真速度行动条 / 双方冻结 / 满条出手 / 命中延迟）。
  4. 免费次数改由服务端记账（`resource_trial_runs.used_free`）。
- ⏭️ **只剩"玩家实机确认"**（AI 看不到屏幕）。若出问题：把 `serverAuthority` 改回 `false` 即回旧玩法。

## 3. 批次与顺序建议

| 批 | 内容 | 理由 |
|---|---|---|
| **批 0** | 建 `resource_trial_runs` 表（幂等、无副作用） | 副本 EF 的前置；顺手把台账里唯一的 ❌ 消掉 |
| **批 1** | **副本**接 `resource-trial` EF（客户端切权威源 + 回放） | EF 已部署、代码现成，一次打通"四步式"全链路 |
| **批 2** | **进化**（最短链路）→ **合成**（骰最多）→ **涅槃**（有不可逆删除） | 三个都是宠物写操作，共用 `pet-settle` EF 与 `duringPetEdit` |
| **批 3** | **打造**（`craft-settle`，依赖装备生成同源） | 产物结构最复杂，放最后 |
| **批 4** | **市集定价**收口（挂单改 RPC / 加校验） | 动 RLS，独立一批 |

**每批之间必须**：`cd docs && npm run check` 零新红 + 浏览器实机看一眼 + 灰度开关（可一键切回客户端）。

## 3.5 ⚠️ 待办：把挂机也改成用公共播放器（**有真障碍，别当顺手活**）

现状：演出**原语**已经共用（`UI.resetBattle` / `animateAttack` / `showDamage` / `updateBars` / `updateAction`），
但**"播一场"的状态机有两套**：
- 挂机：`core/idle-bridge.js` 的 `gaugeTick` + `showTurn` + `showPlan`（内嵌在挂机会话状态机里）
- 副本：`js/ui/battle/show.js`（单场播放器，2026-09-23 新建）

🔴 **障碍：两边的战报模型不是一个东西**——
| | 挂机（battle-settle 的 `script`） | 副本（resource-trial 的 `floors[].events`） |
|---|---|---|
| 粒度 | **每场**一条（t0/t1/win/petHits/enemyHits/hpStart/hpLeft） | **逐刀**（谁在第几毫秒出手、打多少） |
| 伤害来源 | 客户端按刀数**均摊** | 服务端算好的**逐刀数值** |
| 会话 | 连续多场 + 进图/换图/回血等待 | 一层一停 |

⇒ 想合并必须**先统一战报模型**（二选一：让 `battle-settle` 也逐刀下发；或让副本也走"刀数配额"）。
两种都要动线上在跑的挂机核心（线上是活的），**必须单独一批 + 做完让用户挂机实测**。
**别在"顺手改一下"的心态下动它**（2026-09-23 已因此翻车两次）。

## 4. 回滚方案

- **开关**：每处加 `Config.<域>.serverAuthority`（默认 false），走 `game_config_overrides` 可线上关。
- **失败降级**：EF 报错/超时 → 客户端回退到现在的本地实现（**不允许双跑**，双跑=静默双倍）。
- **数据层**：占位行 + 唯一键保证重复提交无害；不做"撤销"，只做"重放同一次结果"。
