# 任务单机制（README）

> **存在的意义**：这个项目是一个人 + 一堆 AI 在干活。没有任务单的时候，
> 会出现「同一个活被两个会话做了两遍」「做完了对不上当初想干什么」「文档结论写反了没人发现」。
> 一张纸解决不了所有问题，但能让**扯皮变少**。

---

## 怎么用

1. 复制 `_模板.md`，改名为 `NN-简短描述.md`（NN 从 01 开始）。
2. 填「要解决什么」和「**边界**」两栏 —— **这两栏必须由人来填**，不许让 AI 自己划边界。
3. 丢给 agent 开工。
4. 干完让它在「六、结果」里写清楚改了什么、有什么 **没做完**。

---

## 🔴 派活四问（决定"这事能不能派出去"）

**1. 边界干净吗？** —— 能不能列出"允许碰哪些文件"？
列不出来就别派，先自己拆。

**2. 会不会动数据库 / 线上配置？**
会 → 不许派给并行 worker，**全局串行，一次一个**。生产库改坏没法撤销。

**3. 验收能不能自动判定？**
不能的（比如"界面好不好看"），派出去就是薛定谔的活 —— 回来你还得自己看一遍，等于没省。

**4. 它撞不撞正在进行的其它任务？**
共享文件（`config.js` / `游戏.html` / `battle.js` / `supabase.js` / `ui-common.js` / `game.css`）
一旦重叠，就必须串行。

## ⭐ 一句话总结（给未来的自己）

**并行省下的时间，往往不够收拾并行制造的麻烦。**
现在这份任务单机制不是为了让你多派活，是为了让你**派出去的活能活着回来**。

真正决定能不能并行的是第 2 问和第 3 问，不是你的心情。
