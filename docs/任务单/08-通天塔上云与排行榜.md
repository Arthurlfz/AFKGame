## 一、要解决什么

> 通天塔成绩（最高楼层/最高腐蚀度）现在只存在浏览器localStorage，换设备就没了，也没法做排行榜。
> 需要把成绩同步到云端，并在排行榜页加塔榜。

## 二、需要改数据库

### 方案：profiles表加两列（轻量）
```sql
alter table public.profiles add column if not exists tower_best_floor int not null default 0;
alter table public.profiles add column if not exists tower_best_corrosion numeric not null default 0;
```

### 同步时机
- `tower-access.js` 的 `recordResult()` 里，破纪录时除了写localStorage，还要update profiles表
- 用现有的 `Items.updateCloudItem` 或直接 `client.from('profiles').update(...)`

## 三、功能范围

- 打塔破纪录时自动写云端
- 排行榜页（已有的 ui-leaderboard.js）加第二个tab："通天塔榜"
- 按 tower_best_floor 降序，前50名
- 自己的排名高亮

## 四、边界

**允许碰的文件**：`docs/js/tower/tower-access.js`、`docs/js/ui/ui-leaderboard.js`、`docs/游戏.html`、CSS
**不许碰**：config.js / battle.js / idle-bridge.js

## 五、验收

```bash
cd docs && npm run check
```
- 打塔破纪录后刷新页面，成绩还在
- 排行榜页能看到全服塔榜
- 换设备登录能看到自己的最高纪录

## 六、结果

**已做（数据库）**：`profiles` 加了 `tower_best_floor int default 0` 与 `tower_best_corrosion numeric default 0` 两列
（`add column if not exists`，可重跑）。已回查 `information_schema` 确认两列都在。

**已做（成绩上云）**：`tower-access.js` 的 `recordResult()` 破纪录时 → 新增 `syncBestToCloud()`，
把 `bestFloor / bestCorrosion` 写进 `profiles.tower_best_floor / tower_best_corrosion`。
- 只在**破纪录时**写，不是每局写（避免频繁写撞限流）。
- **失败不挡流程**：本地那份还在，下次破纪录会再试。
- ⚠️ 这只是「成绩上云」，**不是结算上云**：塔的服务端权威仍然暂停（见 `未决与待办`），我没碰。

**已做（塔榜 tab）**：重写 `ui-leaderboard.js` —— 顶部加「成长榜 / 通天塔榜」切换条，
两个榜**共用同一套行样式与"自己高亮"逻辑**（只换数据源与列含义）：
- 成长榜（原有）：`pets` 按成长降序、每人取最高那只、前 50、join `profiles` 拿昵称。
- 塔榜（新）：`profiles` 按 `tower_best_floor` 降序（同层再比 `tower_best_corrosion`）前 50，
  行内主数值 = 层数、副标题 = "最高腐蚀 N"，**自己没有名次时也能看到"你的排名"**。
- 切换条只在进页面时插一次（`ensureTabs`），之后只切高亮并重拉数据。
⇒ **不建表、不建 RPC、不改数据**，两条查询都用现有表的列。
