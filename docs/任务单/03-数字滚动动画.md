## 六、结果

**实际改了什么**

开工前先查了一遍：**这个功能已经有一份实现了** —— `ui-common.js` 的动效层里就有 `UI.setNum`
（数字变化时滚动 + 弹一下，`num-bump` 动画在 `motion.css`），当时接了 5 个材料计数。
同时另一个会话刚新建了 `ui-countup.js`（`CountUp.to`），只在挂机结算弹窗用了 2 处。
**两份滚动实现 = 项目头号病因**，所以没有再加第三份，而是收口成一份：

1. **删掉 `ui-countup.js`** 和 `游戏.html` 里那行 `<script>`（重复品，删掉而不是共存）。
2. **`ui-common.js` 的 `setNum` 加 `opt.from`**（3 行）——这是唯一缺的能力：
   弹窗/面板里的元素是**新建**的，没有 `__num` 记不到旧值，没有 `from` 就永远滚不起来。
   不补这一行，各处就会各自手写一份 rAF（`ui-countup.js` 就是这么长出来的）。
3. **挂机结算弹窗**（`ui-battle.js`）：经验数字 + 每行材料/装备数量改用 `UI.setNum(b, n, { from: 0 })`，
   行为与原来一致（从 0 蹦到实际值、错开 100ms），但实现只剩一份。
4. **宠物属性**（`ui-pet.js`）：资料页 `pet-atk/def/spd/crit` 与通用面板 `updatePetStatsPanel`
   （`atk/def/spd/crit/critdmg/hit/dodge`，两处共用）改成 `UI.setNum` —— 升级/进化/换装时数字会滚。
5. **鉴定**（`ui-bag.js`）：底部「鉴定石 ×N」加滚动。背包底部每次 `renderBag` 整块重建 ⇒
   元素没有旧值，所以用一个模块变量 `lastIdStoneN` 显式当起点传进去。
6. **新增守值断言**（`vtest_bag.js` 4 条）：`UI.setNum` 存在 / 落值套 `fmt` / 常驻元素落值 / `opt.from` 生效。
   测试环境没有 rAF，走的正是"直接落值"分支 —— 这条断言就是给这个工具留的"坏了会红"的检查。

**有没有留尾巴**

1. **没有在浏览器里看过** —— AI 没有浏览器，§五 那条勾不了。**建议你自己强刷看一眼这 4 个地方**：
   挂机结算弹窗、宠物资料页升一级、装备页属性面板、背包底部鉴定石（鉴定一次看它掉）。
2. **金装揭晓弹窗里的词缀数值没做滚动** —— 那些是每次新建的文本（"+18%"），
   滚动收益小、且揭晓面板本来就有自己的揭晓演出；要加的话一行 `UI.setNum(el, v, { from: 0, fmt })` 即可。
3. **背包里的材料格子（`×N`）没做滚动** —— 整个网格每次重渲染，要滚动得像鉴定石那样逐个补起点，
   成本高于收益，**没做**。
4. 本任务的 `允许碰的文件` 里没写 `ui-common.js`，但**通用动效层的正主就在那儿**
   （它自己的注释写着"全站都要用，所以放通用层"）—— 我只动了 `setNum` 内部 3 行，没碰其它。
