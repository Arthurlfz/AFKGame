## 一、问题描述

### 当前合成机制（有问题）
- 新宠成长值 = **主宠×0.6 + 副宠×0.4**
- 如果副宠成长 < 主宠成长，新宠成长会**低于主宠**（掉成长）
- 示例：主宠成长10，副宠成长5 → 新宠 = 10×0.6 + 5×0.4 = **8**（从10掉到8）
- 玩家必须用等高或更高成长副宠合成，否则掉成长，体验极差

### 原版口袋精灵2合成机制（对齐目标）
- "合成是提高五系宠物成长的主要方法"——合成后主宠cc**提升**，不是降低
- "等级、副宠cc越高，合成用的加成类道具越好，合成后主宠cc的提升也越高"
- "成神后最高只能是60cc所以称为满神"
- "50cc以上均有可能成神，平均100cc左右即可成功"
- "主宠cc越高，成神概率越高，cc达到300不再增加"

### 核心差距
- 当前：合成可能掉成长（加权平均公式）
- 原版：合成永远提升成长（主宠成长+提升值）

### 2.1 合成成长值计算公式（核心改动）

**新公式：合成后主宠成长 = 主宠成长 + 总提升值（永远不掉）**

**总提升值计算（道具加成根据选中道具动态计算）：**
```
基础提升 = 副宠成长 × 0.25
等级加成 = (主宠等级 + 副宠等级) / 200  （上限 +0.5）
道具加成 = 选中道具的 boost 值（合成之石+0.1 / 百变魔石+0.2 / 至尊神石+0.3）
随机加成 = randInt(1, 3)

总提升 = 基础提升 × (1 + 等级加成 + 道具加成) + 随机加成
合成后主宠成长 = 主宠成长 + 总提升
```

**神级宠概率（根据选中道具变化）：**
- 合成之石：30%概率出神级宠
- 百变魔石：60%概率出神级宠（随机出神级宠）
- 至尊神石：100%出神级宠，终阶等级要求降到Lv50（对齐原版"至尊神石降低等级要求"）

**保底规则：**
- 合成后主宠成长 **≥ 主宠成长**（永远不掉，最低等于主宠成长）
- 即使副宠成长为0，总提升至少为随机加成(+1~3)

**示例：**
- 主宠成长10，副宠成长5，都40级，选中合成之石（+0.1）：
  - 基础提升 = 5×0.25 = 1.25
  - 等级加成 = (40+40)/200 = 0.4
  - 道具加成 = +0.1
  - 随机加成 = +2（取中间值）
  - 总提升 = 1.25×(1+0.4+0.1) + 2 = 1.25×1.5 + 2 = 1.875 + 2 = 3.875 ≈ 4
  - 合成后主宠成长 = 10 + 4 = **14**（从10涨到14，不掉！）
  - 神级宠概率：30%

- 主宠成长10，副宠成长5，都40级，选中至尊神石（+0.3，Lv50终阶要求）：
  - 总提升 = 1.25×(1+0.4+0.3) + 2 = 1.25×1.7 + 2 = 2.125 + 2 = 4.125 ≈ 4
  - 合成后主宠成长 = 10 + 4 = **14**
  - 神级宠概率：100%（必定出神级宠）

- 主宠成长60，副宠成长70，都60级，选中至尊神石（+0.3）：
  - 基础提升 = 70×0.25 = 17.5
  - 等级加成 = (60+60)/200 = 0.6（但上限0.5，取0.5）
  - 道具加成 = +0.3
  - 随机加成 = +2
  - 总提升 = 17.5×(1+0.5+0.3) + 2 = 17.5×1.8 + 2 = 31.5 + 2 = 33.5 ≈ 34
  - 合成后主宠成长 = 60 + 34 = **94**（但如果出神级宠，上限60，超过部分折算加成）

### 2.2 神级宠合成（成神）特殊处理

**门槛（根据道具变化）：**
- 主宠和副宠都必须是终阶（进化5阶），**等级要求Lv60**
- 使用至尊神石时，终阶等级要求降到**Lv50**（对齐原版"至尊神石降低等级要求"）
- 主宠和副宠成长值都必须≥60
- 消耗选中的合成道具（合成之石/百变魔石/至尊神石）

**概率（根据选中道具变化）：**
- 合成之石：30%概率出神级宠
- 百变魔石：60%概率出神级宠（随机出神级宠，对齐原版"百变魔石随机出神"）
- 至尊神石：100%出神级宠（对齐原版"至尊神石必定出神"）

**神级宠出生成长值（方案C：成神上限60+超过部分折算）：**
```
计算成长 = 主宠成长 + 总提升（用上面的新公式）
出生成长 = min(计算成长, 60)  （成神上限60，满神）
超过部分 = max(0, 计算成长 - 60)
statCoeff额外加成 = min(超过部分 × 1%, 20%)  （每超过1点+1%，上限+20%）
最终statCoeff = 普通终阶×1.5 × (1 + statCoeff额外加成)
```

**示例：**
- 主宠成长65，副宠成长70，计算成长=94（见上面示例）
- 出生成长 = min(94, 60) = **60**（满神）
- 超过部分 = 94 - 60 = 34
- statCoeff额外加成 = min(34×1%, 20%) = **20%**（触上限）
- 最终statCoeff = 普通×1.5 × 1.2 = 普通×**1.8**

**设计意图：**
- 跟原版对齐：成神后最高60cc（满神）
- 鼓励玩家用高成长副宠合成：超过越多，statCoeff加成越多
- 超过部分不浪费：折算成永久属性加成
- 神级宠出生不会太强（上限60），但高成长素材合成的神级宠statCoeff更高
- 涅槃可以突破60上限（叠成长是长线追求）

### 2.3 普通合成（不出神级宠）

**变异宠（·异变）：**
- 50%概率出变异宠（保持现有）
- 变异宠成长 = 主宠成长 + 总提升 + 额外变异加成(+1~3)
- 变异宠额外多1条随机特质（保持现有）

**普通新宠：**
- 50%概率出普通新宠（保持现有）
- 普通新宠成长 = 主宠成长 + 总提升
- 继承主宠形态和成长系数（保持现有）

**成长值软上限（可选，建议加）：**
- 普通宠（非神级）成长值软上限：100
- 超过100后，总提升值减半（控制膨胀，但不卡死）
- 神级宠无软上限（涅槃可以无限叠）

### 2.4 涅槃道具系统（简化版）

**涅槃规则（保持现有）：**
- 只有神级宠才能涅槃
- 主宠等级重置为1，副宠消失
- 消耗涅磐兽×5（现有机制，保持不变）+ 可选涅槃丹（加乘吸收）

**涅槃道具效果（1种）：**

| 道具名 | 效果 | 对齐原版 |
|---|---|---|
| 涅槃丹（普通） | 吸收加乘：主宠成长 += 副宠成长 × 50% × 1.2（20%额外加乘） | 涅槃丹（常规涅槃加成道具） |

**使用条件：**
- 涅槃丹：无条件可用（可选道具，不消耗则按默认50%吸收）

**设计意图：**
- 涅槃丹作为可选加乘道具，提升涅槃效率
- 不改变现有涅槃核心机制（消耗涅磐兽×5、50%吸收）
- 保持简单，避免道具过多导致玩家困惑

### 3.2 `docs/js/pet/pet_merge.js`

**修改点：**
1. 合成逻辑（synthesize）：
   - 替换旧公式 `growth = main.growth * mainW + sub.growth * subW`
   - 新公式：`growth = main.growth + calcTotalBoost(main, sub, hasPill)`
   - 新增函数 `calcTotalBoost(main, sub, hasPill)`：
     ```javascript
     function calcTotalBoost(main, sub, hasPill) {
       const S = (Config.pet && Config.pet.synthesize) || {};
       const baseBoost = (sub.growth || 0) * (S.baseBoostRatio || 0.25);
       const levelBoost = Math.min(((main.level || 1) + (sub.level || 1)) / 200, S.levelBoostMax || 0.5);
       const stoneBoost = S.stoneBoost || 0.1; // 合成默认消耗合成之石
       const pillBoost = hasPill ? (S.pillBoost || 0.3) : 0;
       const randomRange = S.randomBoost || [1, 3];
       const randomBoost = randInt(randomRange[0], randomRange[1]);
       const totalBoost = baseBoost * (1 + levelBoost + stoneBoost + pillBoost) + randomBoost;
       return Math.max(1, Math.round(totalBoost)); // 至少+1
     }
     ```
   - 保底：`growth = Math.max(growth, main.growth)`（永远不掉）
   - 普通宠软上限：如果不是神级宠且 growth > 100，`growth = 100 + (growth - 100) / 2`（超过部分减半）
2. 神级宠合成：
   - 用神级宠出生上限60：`godGrowth = Math.min(growth, 60)`
   - 超过部分折算statCoeff：`excess = Math.max(0, growth - 60)`，`statCoeffBonus = Math.min(excess * 0.01, 0.20)`
   - 神级宠statCoeff = 普通终阶×1.5 × (1 + statCoeffBonus)
3. 变异宠：
   - 变异宠成长 = growth + randInt(1, 3)（额外变异加成）
   - 保底：变异宠成长 ≥ main.growth + 1

## 五、Anti-Pattern（绝对不能做的事）

### 5.1 数值相关
- ❌ **禁止继续使用加权平均公式**（主×0.6+副×0.4），这个公式会掉成长
- ❌ **禁止合成后主宠成长低于主宠成长**（永远不掉，保底必须有）
- ❌ **禁止拍脑袋定提升值**：所有提升值必须用公式计算，公式参数在config.js里可配置
- ❌ **禁止神级宠出生成长超过60**（满神上限，超过部分必须折算）
- ❌ **禁止超过部分浪费**：超过60的部分必须折算成statCoeff加成，不能直接丢掉

### 5.2 系统设计相关
- ❌ **禁止破坏现有神级宠系统**：只能修改成长值计算公式，不能删除/改动神级宠的获得门槛、概率、特性
- ❌ **禁止破坏变异机制**：变异宠50%概率、额外+1~3、额外特质，保持不变
- ❌ **禁止神级宠能合成**：神级宠只能进化和涅槃，不能作为合成素材
- ❌ **禁止去掉道具消耗**：合成/进化/涅槃必须消耗对应道具（保持现有）
- ❌ **禁止道具效果硬编码**：所有道具效果（boost/godChance/absorbRatio/type）必须在config.items里配置，UI从配置读取
- ❌ **禁止道具下拉框只在一个页面做**：合成/进化/涅槃三个页面都必须有道具下拉框
- ❌ **禁止道具不足时可点击**：道具不足时对应选项和操作按钮必须置灰
- ❌ **禁止改变普通道具的现有掉落**：强化丹A/B、天仙玉露、合成之石、涅槃丹、涅磐兽的掉落地图和概率保持不变，只新增稀有道具的获取途径
- ❌ **禁止稀有道具挂机掉落**：百变魔石、至尊神石只能通过BOSS掉落/循环任务兑换/成就奖励获得，不能加入普通挂机掉落池
- ❌ **禁止稀有道具掉落占用普通掉落位**：BOSS稀有道具掉落必须与普通掉落独立，不能替换普通掉落
- ❌ **禁止兑换无周上限**：百变魔石的循环任务兑换必须有每周限换5个的上限，控制产出速度

### 5.3 代码架构相关
- ❌ **禁止硬编码公式参数**：所有参数（baseBoostRatio、levelBoostMax、stoneBoost、pillBoost、randomBoost等）必须放在config.js里，不能写死在代码里
- ❌ **禁止只改前端不改服务器**：config.js 和 config-server.mjs 必须双份一致
- ❌ **禁止不写测试**：新公式必须有单元测试覆盖所有边界条件
- ❌ **禁止不同步UI**：合成界面必须显示成长预览，不能只改逻辑不改UI

### 5.4 部署相关
- ❌ **禁止只部署前端不部署Edge Function**：如果改了服务器配置，必须重新部署battle-settle
- ❌ **禁止不验证就提交**：所有测试通过+手动测试后才能git提交
