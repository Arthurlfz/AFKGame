## 二、新增的守值测试

**`docs/tests/vtest_irreversible_guard.js`**（12 条断言，全过）

守一条底线：**玩家手里的东西不会因为他"点了一下 / 按了一下键"就永久消失。**

- ① 任何分解入口必须先过确认，不许直接调 `salvageList`
- ② 快捷键只在"背包开着 + 焦点不在输入框"时才生效
- ③ 引导 spotlight 的 `#id` 锚点在页面上必须存在
- ④ 即使锚点真丢了，气泡也必须照常显示（不许整块消失）

> 分解/丢弃/吞噬这类不可逆操作以后还会再加，这条底线不能靠人记。

**顺手修的 flaky**：`vtest_marketbot` 的「等级档分布 / 流派分布」
原写法是**拿单批 20 个 persona 的绝对个数卡下限**（新手 ≥4 / dps ≥6），
而 persona 是按权重随机抽的 → 时红时绿（实测连跑：新手 3~9、dps 6~16），
周期性污染回归基线。
改成**抽 60 批共 1200 个样本断言比例贴近配置 ±6pp**（沿用 09-12 修 `vtest_tier_rarity` 的先例）。
连跑 5 次全绿，实测比例 38~41.5% / 43~45.6% / 14~17%，紧贴配置 40/45/15。

## 五、教训（给未来的我）

1. **汇报前先问：我这份东西，换任何一个挂机游戏都成立吗？**
   成立 = 通用检查表 = 没读项目。**用户一眼就能看出来。**
2. **老文档会骗人。** `docs/档案/新手引导·奖励闭环设计_v1.md`（09-08）通篇讲 G 链和凝魂晶石，
   而这两样 09-16 就死了（g 链被 `filter` 踢掉换成 n 链；凝魂晶石整套退役）。
   引用旧文档前必须逐条对代码。
3. **「功能没生效」先查可发现性，再查逻辑**；**「点了没反应」先查目标存不存在**。
   这次 5 条 A 档里有 3 条属于这两类。
4. **不可逆操作默认要确认**，而且要写成测试守住 —— 人会忘，测试不会。

## 六、🔴 更正：本文初版有一处结论是错的（2026-09-17 当天被用户指出）

**这句话是错的，逐条核实结果：**

| 道具 | 我说的 | 实际（代码核实） |
|---|---|---|
| **涅槃丹** | Lv25~55 拿不到 | 🔴 **这东西 Lv25~55 根本用不上**。涅槃门槛 = 双宠 Lv60 **且必须是神级宠**（`pet_merge.js:177-186`）。把它算进"这一段空档"是硬错 |

而且这三样都是**加成道具**（进化 +20% / 进化 +30% / 打造锁定词缀），
不是必需品 —— 没有它们照样能进化、能打造，只是加成少一点。
