## 0. 背景与定位（重要前提）

**用户想起原设计：1-100 级爬升本来就是 "教学"。**

由此得出三个判断：



1. **等级爬升不是游戏本体**，只是热身 / 教学。真正的游戏是爬完等级之后的**无限循环**：涅槃成长 + 做装 + 市场博弈。

2. 配合 60 级封顶：教学 = 1-60；60 之后进入真玩法（深图产出好货 → 市场 / 倒卖 → 涅槃循环）。两者自洽。

3. **AI 假人经济 = 后期核心玩法**，不是冷启动补丁。玩家毕业后的 "对手戏" 就是和整个模拟市场博弈 —— 识货、捡漏、倒卖、比谁更懂价。

因此 AI 系统按 "可长期演化的核心系统" 设计，而不是一次性 bot。

## 1. 设计目标（一句话）

> 让市场永远 "有人、有货、有成交"，并且时不时给玩家 "捡到便宜、卖对高价" 的爽点，同时长期不崩盘。

可验收目标（原型阶段全部可测）：



| # | 目标   | 验收口径                           |
| - | ---- | ------------------------------ |
| 1 | 供给足  | 市场随时 20+ 件在售，偶尔出现 "明显低于价值" 的漏  |
| 2 | 需求足  | 玩家挂单在合理价格下能被消化，有 "卖掉了" 的成交反馈   |
| 3 | 可博弈  | 玩家能靠识货 / 定价赢过 AI（买到漏、高价卖出）     |
| 4 | 不崩盘  | 长期无通胀通缩，材料购买力大致稳定              |
| 5 | 有真实感 | AI 有昵称 / 等级 / 行为，玩家不违和（或分不清真假） |

## 2. AI 玩家本体（population）

20\~80 个常驻虚拟玩家（原型 20 起，正式多人再按需扩），每个是一组**参数**，不跑真实战斗循环。

> 为什么 20 就够：三个分群分布 × 20 全部凑整 —— 等级档 40/45/15 × 20 = 8 新手 / 9 中坚 / 3 毕业；流派 55/25/20 × 20 = 11 输出 / 5 坦克 / 4 速度；行为分群 20/60/20 × 20 = 4 新手 / 12 中坚 / 4 大佬。20 个即可完整覆盖市场谱系 + 需求结构，前端沙箱跑起来也更轻。

每个 AI 拥有：



| 字段       | 说明                        | 作用                       |
| -------- | ------------------------- | ------------------------ |
| 昵称       | 暗黑风词库随机组合                 | 出现在挂单 / 交易记录里，营造 "有人"    |
| 等级档      | Lv30\~Lv60+（模拟 "有人毕业了"）   | 市场有层次                    |
| **血统偏好** | 喜欢哪只宠 / 哪类词缀              | 决定它买什么、为什么会 "识货不足"       |
| 钱包       | 材料余额                      | **自平衡核心**：卖入 - 买出，AI 不印钱 |
| 行为参数     | 产出速度 / 购买倾向 / 价格敏感度 / 犯错率 | 调参控制市场活性                 |

**分群**（让市场有生态，而不是一坨机器人）：



| 群     | 占比    | 行为                |
| ----- | ----- | ----------------- |
| 新手 AI | \~20% | 挂垃圾、定价乱、容易被捡漏     |
| 中坚 AI | \~60% | 正常买卖，是市场主力        |
| 大佬 AI | \~20% | 收好货、挂毕业装、偶尔甩漏（大漏） |

## 3. AI 行为三腿闭环（核心模型）

AI 玩家只做三件事，形成闭环：



```
\[腿1 产出] → {大部分自用 / 小部分挂市场}

&#x20;             ↓

&#x20;        \[市场] ←⇄→ \[腿2 购买]（按血统偏好 + 缺什么买什么）

&#x20;             ↓

&#x20;        \[腿3 消耗]（买走的装备/材料 → 用于"变强"→ 离场消失）

&#x20;             ↓

&#x20;     钱包自平衡（卖的收入 - 买的支出）
```



* **腿 1 产出**：AI 按参数 "模拟挂机" 产出装备 / 蛋 / 材料。大部分自用（穿 / 分解 / 养宠），小部分挂市场。产出节奏受控（详见 §8）。

* **腿 2 购买**：AI 缺什么买什么（血统偏好 + 战力提升逻辑），玩家单和 AI 单都买。买走 = 消耗。

* **腿 3 消耗**：AI 买到的东西转化为 "战力参数" 提升（纯数值模拟），偶尔 "涅槃" 重置再变强。**商品离场 = sink。**

* **钱包自平衡**：每个 AI 的支出 ≤ 收入（或净支出受控），AI 群体不凭空印钱。这是长期不通胀的根本保障。

## 4. 定价模型 + 犯错机制（捡漏 / 倒卖的来源）

### 4.1 价值模型（AI 的 "合理价"）



```
价值 = 物品基础价

&#x20;    \+ 词缀 / T 阶加成

&#x20;    \+ 成长值加成（宠物/蛋）

&#x20;    \+ 稀有度加成

&#x20;    \+ 血统匹配加成（AI 对自己偏好的血统更舍得）
```

AI 用这个模型定价，也用它判断 "该不该买"。

### 4.2 犯错（制造 G 点）



| 犯错                                                  | 概率                   | 效果                              |
| --------------------------------------------------- | -------------------- | ------------------------------- |
| **挂漏**：AI 把好货挂出明显低价                                 | \~5\~8%（大佬 AI 偶尔挂大漏） | 玩家识货捡漏                          |
| **买贵**：AI 用高于市价买走玩家单                                | \~3\~5%              | 玩家高价卖出爽点                        |
| **识货盲区**：AI 价值模型覆盖不到的组合（如血统绑定词缀对特定 AI 特别值钱，但定价没算进去） | 常态                   | **玩家识货空间的来源**：低价买到 → 转手卖给对口的 AI |

> 关键设计：
>
> **让 AI 对 "特定血统 / 词缀组合" 的价值评估有盲区**
>
> ，这正是玩家 "比 AI 更懂价" 能赢钱的空间。没有这个盲区，市场就没有博弈。

### 4.3 防呆（配合红线）



* AI 不买 "高于价值模型上限" 的玩家单。

* AI 挂单价不脱离价值模型范围（AI 自己不挂天价当锚）。



***

## 5. 两条红线（防崩，必须写进代码）



1. **消耗端必须存在**：AI 买走的东西必须离场（被用掉 / 消失）；材料被 AI 消耗（做装 / 进化 / 涅槃）。**禁止买回来的东西再回流市场**（除非按 §8 的 "回收但降价" 规则）。

2. **价格合理判定**：AI 只买不高于 "价值模型上限" 的单。防止玩家挂天价垃圾单刷材料。

> 这是 AI 系统不变成 "印钞机" 的两道闸。少一道，经济必崩。

## 6. 玩家可感知的时刻（6 个）



1. **上架被买** → "卖掉了！"（需求满足）

2. **逛市场见漏** → 识货捡漏（核心爽点）

3. **挂高价卖不掉** → 学会定价（隐性教学）

4. **低价买入 + 转手高价** → 倒卖成立（长期玩法）

5. **交易记录里 AI 活跃成交** → 市场 "热"（真实感）

6. **买到 AI 挂的毕业装** → 前期强装来源（供给端价值）

## 11. 价格锚点方案（怎么定 "合理价"）・2026-09-03

> 已拍板：AI 不标 "AI / 流浪商人" 标记，作为真实玩家呈现。
> 本方案回答：AI 定价 / 买入 / 玩家参考价，用什么当 "尺"。

### 11.1 核心思路（两层，不矛盾）

> **尺（魂值）是死的，市场（价格）是活的。**

用户两个要求并不冲突：



* 想要 "稳定可读的锚" → **魂值**（公允价，策划定，不随供需动）。

* 想要 "真实的交易市场"（抄底 → 短缺 → 增值）→ **市场价**（成交均价，随供需 / 炒作波动）。

魂值的用处恰恰是**让波动可读**：抄底重铸石 → 市场价飙到魂值之上 40% → 玩家从比价标签看出 "溢价了"，可以跟着炒，也可以等回落。没有这把死尺，你分不清 "这是不是被炒高了"。

### 11.2 三层结构



| 层              | 是什么                                                                                  | 动 / 静                         |
| -------------- | ------------------------------------------------------------------------------------ | ----------------------------- |
| **1 魂值（成本底线）** | 一张 "魂值基准表"（抽象点，策划定）：装备 = 部位 + 底材 T + 词缀条数 + 词缀 T+Roll；宠物 / 蛋 = 品种 + 成长值 + 特质；材料 = 档位 | **静**：= 生产成本（地板），不随供需动，策划手动维护 |
| **2 市场价（活市场）** | 每个品类维护 "成交移动平均价"（近 N 笔加权），由真实成交喂养：玩家买 AI / AI 买玩家 / 玩家买玩家                            | **动**：随供需 / 抄底 / 短缺波动         |
| **3 个人估值**     | 每个 AI 偏好系数（喜欢血统 ×1.2、不喜欢 ×0.8）+ 随机波动 + 犯错（挂漏 / 买贵）                                   | 围绕市场价 ± 个人口味                  |

**AI 定价 / 买入看市场价（动态），但魂值兜底（安全带）**：市场价可以偏离魂值，但 AI 不追离谱的溢价 / 压价 —— 这是防止纯情绪化泡沫的闸。**注意：魂值是 "地板"（生产成本），不是 "价格"（需求定的）—— 热装价格远高于底线，冷装贴着底线。**

### 11.3 为什么 "尺" 不挂在材料上（凝魂晶石会贬值）



* 凝魂晶石会结构性贬值：产出随玩家变强无限增长，需求有限 → 供大于求 → 长期贬值。任何 "靠游戏时间自然产出" 的材料都躲不掉。

* 所以 "尺" 不能是会缩水的材料，得是策划定的**抽象魂值**（不跟任何材料挂钩，不贬值）。

* 但 "市场价" 是另一回事：**市场价就该随供需动**（包括凝魂晶石自己的市场价也可以涨跌）—— 动的是市场价，不是尺。

### 11.4 AI 作为真实玩家的互动规则



* **挂单**：价 = 市场价 × 个人系数 × (1± 波动)，且不脱离 \[魂值 × 下限，魂值 × 上限] 的合理带；偶尔犯错挂漏。

* **买入**：价 ≤ min (市场价 × 个人系数上限，魂值 × 溢价上限)；超了不买（红线 2）。

* **AI 对短缺有反应**：某材料缺货（市场价走高）→ AI 卖家挂更高、买家心理价上限上调，但存在 "有耐心的 AI" 选择等不追高（可调参数）。

* **AI 之间不互相交易**：理由 = 对倒 / 洗单，伪造成交量和市场热度，玩家看到大量假活跃记录会出戏；市场价只吃 "有玩家参与的真实成交"。

* 不标 "AI / 流浪商人"：挂单、交易记录里只显示昵称，玩家分不清真 AI。

* "市场热度" 靠 AI 挂单更新 + AI 买玩家单的成交；AI 购买加 "分批 / 延迟 / 偶尔不买"，避免像自动机秒买。

### 11.5 玩家标尺（动态比价）



* 市场每件商品显示**动态比价**："比近期市场均价低 30%"（漏）/ "高 15%"（贵），另显示距魂值溢价："重铸石较公允价 +40%"。

* 抄底 / 倒卖可读：玩家扫货 → 比价标签从 "平" 变 "溢价" → 其他人看到溢价开始抛售 → 价格回落。这一整条链就是 "真实交易市场"。

* 不显示绝对 "几颗晶石"，用相对数（单位抵消、抗材料贬值）。

### 11.6 校准规则（防泡沫 / 防崩）



| 信号                  | 做法                            |
| ------------------- | ----------------------------- |
| 某品类市场价长期偏离魂值（炒作或低估） | 策划手动调魂值表对齐真实成本；短期偏离由市场自纠      |
| 某材料被抄底缺货 → 溢价过高     | 高价吸引囤货玩家抛售 → 自动恢复；AI 不追离谱溢价兜底 |
| 某材料库存暴增             | 市场价自然下行；策划可调产出 / 增加消耗         |
| AI 钱包净额长期为正（玩家刷 AI） | 调低犯错率 / 收紧买入上限                |

### 11.7 抄底情景走读（验收样例）

> 玩家扫光在售重铸石 → 供给短缺 → AI 与玩家抢购 → 市场价上涨（相对魂值 +40%）→ 比价标签显示 "溢价 40%" → 高价吸引囤货者抛售 → 供给恢复 → 价格回落。

**验收**：这个链条能被玩家真实操作触发，且 24 小时内自然回落（不靠策划干预）。

### 11.8 需求结构从哪来？——AI 玩家真的在 "玩"（2026-09-03）



* **魂值设不出需求**：前期大家都玩 DPS → DPS 装需求大、价高；坦克装冷门、贴着成本。这是玩家 "玩什么" 决定的，策划没法预先猜准。**所以 "哪件装备值钱" 不能写死，只能让市场自己长出来。**

* **需求结构由 "真实 AI 玩家" 提供**：每个 AI 有真实流派偏好（血统 + 属性优先级），且**偏好分布模拟真人**：


  * 前期：多数 AI 偏好 DPS 向（例 60% 输出 / 20% 坦克 / 20% 速度）→ DPS 装被抢购 → 市场价高于魂值底线；坦克装少人问津 → 贴着底线甚至略低于。

  * 后期：60 级深图（图 11-17）生存变重要 → AI 偏好迁移 → 冷门变热。**这就是活 meta，市场跟着动。**

* **策划的杠杆不是 "写死每件装备值多少"，而是 "调 AI 流派分布"**：想捧某玩法 → 提高对应 AI 占比 → 需求上来 → 价格上来。

* **AI 真玩 = 它会买自己流派需要的装备、用掉、再产新的**（产出 / 购买 / 消耗闭环），所以需求是持续、真实的，不是一次性脚本。

* 材料比例保持固定（此前拍板）：材料 = 像钱（稳定）；装备 / 宠物 = 像商品（价格随需求浮动）。**钱稳、货活，不矛盾。**

## 12. AI 实现架构：真实账号 + 决策大脑（2026-09-03 拍板方向）

> 用户方向：AI 不只是 "参数设定"，而是真的给 AI 配账号去玩 —— 产出、掉落、打造、进化全走真实游戏代码，市场从真实玩法里长出来。
> 澄清：这不是 "全自由 AI"，是两层结构 ——
>
> **底层真实、上层可控**
>
> 。

### 12.1 两层结构



| 层           | 是什么                                                                          | 谁说了算     |
| ----------- | ---------------------------------------------------------------------------- | -------- |
| **底层：真实账号** | AI 复用真实游戏代码（掉落池 / 战斗 / 打造 / 进化 / 涅槃 / 背包），在**独立沙箱**里跑，不占真实玩家 DB、不碰 RLS、不被登录拦 | 真实游戏逻辑   |
| **上层：决策大脑** | 行为模型：玩什么流派（偏好分布）、留什么卖什么（需求判断）、挂什么价（定价）、买不买（价格合理判定）、犯不犯错（犯错率）                 | 参数化，策划可调 |



* 真实账号提供 "产出的事实"：AI 挂出来的装备是真词缀真 Roll 的真装备；AI 的进化 / 涅槃是真消耗了真材料。**市场的供给和需求全是 "真玩出来的"。**

* 决策大脑提供 "行为的理由"：真玩只回答 "产出了什么"，不回答 "为什么这么干"。没有决策层，AI 只会囤货、不参与市场。

### 12.2 这样带来的额外好处



* **魂值可以 "实测"**：跑一遍真实模拟，量出 "一把图 17 的 T1 金装到底要挂多久 + 多少材料"—— 魂值不用策划拍脑袋，是实测生产成本。

* 需求结构自动跟随真实玩法：AI 账号真的在玩 DPS 流派 → DPS 装需求真实成立，不是脚本编的。

### 12.3 落地要点（原型）



1. AI 账号跑在独立内存态（不进真玩家数据库），但**复用同一套 js 逻辑**（drop/battle/craft/pet）。

2. **节拍模拟**：挂机游戏天然适合 —— 每个 AI 每几秒 / 几分钟 tick 一次，不用实时战斗。

3. 决策层是 AI 玩家 "像真人" 的关键，参数集中在 config（偏好分布 / 需求 / 定价 / 犯错 / 迁移时机）。

4. 防崩红线不变：价格合理判定（不买离谱单）、AI 之间不交易、消耗端存在。

### 12.4 分步走（升级不是推倒）



1. **第一步**：参数模拟版 AI（现有方向）跑通市场闭环、验证玩法。

2. **第二步**：把 AI 的 "产出 / 消耗" 换成真实游戏代码（真实掉落 / 打造 / 进化），决策层保留。

3. **第三步**：打磨 meta 迁移 + 实测魂值表。

### 12.5 诚实提醒



* 真玩 ≠ 玩家永远分不清：AI 名字会重复、全天在线等破绽仍在。目标不是完美伪装，是**市场像活的、行为可信**。

* 真实账号增加实现量（要复用战斗 / 掉落 / 打造代码 + 写决策层 + 沙箱），但对你 "真实交易市场" 的目标，这是对的方向。

## 14. 技术实现方案（两阶段）

### 14.1 阶段 1：前端沙箱 N persona（改现有 market\_bot.js，原型先用）

**关键点**：每个玩家浏览器各自跑一份 AI 经济 → **只在自己眼里成立**。对单人测试（现在）够用，但这不是 "共享市场"。

改造点（对现有代码）：



1. `config.js`：marketBot 换成 personas 配置（见 §13）。

2. `market_bot.js`：

* 生成 20 个 persona（昵称用 Config.auth.nickname 词库拼、不重名；等级档 + 流派按分布抽）。

* 每 tick 每个 persona：按 areaTier 产出（复用真实掉落逻辑，但不写玩家库）→ 决策（按流派评估，自用 / 挂卖 / 分解）→ 挂单（定价 = 运行锚 × 个人系数 ×(1±jitter)，夹魂值带）。

* 购买：persona 定期扫玩家挂单，按流派需求 + 合理价判定，走现有 buyAsBot（记录 persona 昵称）。

* 消耗：买入 80% 离场（sink），20% 降价再挂。

1. `market.js`：加 "运行锚"（成交移动平均价）按品类维护；挂单对象带 personaId/nickname（不标 AI）。

2. `main.js`：startGameRuntime 改为启动 personas（替代原 MarketBot.start）。

**阶段 1 落地记录（2026-09-03）——"AI 上架不全面"修复**：

* 现状问题：`market_bot.js` 的 `makeListing` 调 `generateEquipment(rarity)` 没传图档 → 所有 AI 货恒为图1档 × 底材T3 的白板；且定价用固定 `prices` 表无档位梯度。市场逛起来全是低级货，玩家没得挑。
* 已改（代码已落盘 + 测试通过）：AI 上架改走**真实掉落**（`rollReward(dry)`，按 `config.marketBot.areaWeight` 抽挂机图档，图档决定稀有度/底材T），定价改 **`priceGradient`**（价 = 1.5^(图档-1) × 稀有度乘数 × 材料系数）。
* 实测抽样（2000 次 dry）：AI 挂机图档覆盖图1~17（中段 7/9/11 最重）；装备稀有度 gold13/blue15/white4（深图金多）；底材 T1~T5 都有；定价梯度 white@图1≈1 材料 → gold@图17≈1565 材料。市场从"图1白板"变成"全谱系可识货"。
* 待办（下一块）：**AI 上架材料 + 宠物蛋**（AI 真实掉落里 material≈24%、蛋≈1.4%，现在只上架装备、材料/蛋被丢弃）——需要市场 UI 支持渲染这两类 bot 挂单，属独立改动。
* **二阶段落地（2026-09-03）——材料 + 宠物蛋上架已做**：`config.marketBot.botGoods`（材料兑换表 `{sold: {pay, qty}}` + `eggPrice`）、`market.js` 加 `botMaterialListings/botEggListings` + `buyBotMaterial`（以物易物：扣收款材料→买到的材料入包→移除）/`buyBotEgg`（扣款→`Drop.grantEgg` 蛋入包→移除）、`market_bot.js` 加 `makeMaterialListing`（AI 卖 1 单位材料，收款物/数量按表）+ `makeEggListing`（品种从 `Config.pet.starters` 随机，价按 `eggPrice`）+ tick 维护 `minMaterial=8/minEgg=5`、UI 市场加「🧪 材料」区 + 蛋区合并 AI 假蛋单（`getEggListings` 含 bot，不标"我的"）。测试：`vtest_marketbot.js` 新增步骤 10（材料/蛋结构 + 购买 + 入包 + 移除）全过。
* **三阶段落地（2026-09-03）——20 个 AI persona（替代单一"流浪商人"）已做**：
  * `config.marketBot.personas`：`count:20`（用户拍板 20 就够，等级档 40/45/15 ×20=8/9/3、流派 55/25/20 ×20=11/5/4 全凑整）+ `levelTiers`（新手图1-4/中坚图5-10/毕业图11-17）+ `playstyles`（dps 55/tank 25/speed 20，`statPriorities` 定词缀口味）+ `wallet` + `behavior`（自用率/消耗率/挂漏/买贵/定价波动/耐心/挂单上限/购买间隔）。
  * `market_bot.js` 重写：`generatePersonas()`（20 个昵称不重名、等级档+流派按分布抽、每人 leaks/overpay/patient 随机）→ 挂单全部带 **persona 昵称**（装备按 persona 图档范围真实掉落 + 定价带**流派口味 ×个人波动±jitter × 挂漏**；宠物/材料/蛋同）→ 买家随机 persona 出手，**按流派 statPriorities 打分挑目标** + 只收合理价 + 小概率买贵 + patient 只等低价 → 买入 **80% 消耗离场（sink）/20% 降价再挂**（防刷材料漏洞）。顺带修复宠物定价 bug：`petHighGrowth` 12→7（婴儿成长 3~8，旧值永不触发高档价）。
  * UI：四类卡片（装备/宠物/蛋/材料）meta 行都显示卖家昵称（`l.seller`），购买 toast 也带昵称。
  * 测试：`vtest_marketbot.js` 步骤 3b（persona 数量=配置 20、昵称不重名、等级档/流派分布合理、`gearAffinity`：dps 更想要 atk 词缀 1.40>hp 1.00）+ 卖家断言改 persona 昵称；`vtest_botbuy.js` 恢复 pickBuyTarget"只收便宜货"语义后全过。5/5 + 3 套回归全绿。
  * **已知边界**：云端 `bot_buy_equip` RPC 的交易记录买家仍写"流浪商人"（服务端硬编码，阶段 2 才改成 persona 昵称）；persona 钱包（`wallet`）阶段 1 为装饰性状态，阶段 2 服务端接真实钱包做"卖入-买出自平衡"。

### 14.2 阶段 2：服务端 AI（真共享市场，正式做）

**关键点**："真实账号真玩" 要成为所有人看到的一个市场，**AI 必须跑在服务端**，不能各浏览器各跑一份。



1. 把核心逻辑从 "挂 window 的 IIFE" 解耦成可 import 的纯函数（drop/equipment/pet/materials）。

2. 部署一个 Cloudflare Worker（项目已有 wrangler.toml）+ Cron Trigger（每 1\~5 分钟 tick 一次）：

* 读 AI 状态表 → 逐 persona：产出 → 决策 → 挂单写 item\_listings / 购买走 bot\_buy\_equip → 更新移动平均价。

* AI 挂单真落库，所有玩家看到的市场是同一个。

1. AI "账号" = 一张 ai\_players 表（或系统行），不占玩家登录 / RLS。

2. 防崩红线保留：价格合理判定、AI 不互买、消耗端存在。

### 14.3 建议



* **现在**：只做阶段 1（20 个 persona 前端沙箱），验证 "动态市场手感 + 流派需求结构"。

* **要多人同市场时**再上阶段 2（Worker），阶段 1 的决策大脑逻辑直接搬到 Worker 复用。
