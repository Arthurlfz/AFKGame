# Forge of Souls：战斗伤害公式重设计 v1

> 日期：2026-09-09
>
> 状态：**已实施**（三份战核 + 两份派生文件 + 服务端 EF 已部署，全量 vtest 通过）
>
> 目的：换掉「攻击 − 防御」这套减法伤害，从根本上解决「玩家后期完全免伤、挂机没有任何压力」的问题。
>
> 权威边界：数值唯一事实源仍是 `docs/js/core/config.js`；本文只定公式与验收口径，具体数字以实施后实测为准。

---

## 1. 现在的公式有什么问题

一次攻击现在是这么算的（`battle.js` / 两份 `battle-sim.mjs` 里同一行）：

```
实际伤害 = 攻击 − 防御（最低 1）
```

**问题一：装备一穿，伤害直接归零。**
怪的攻击是写死的（`areaEnemyStats.atk`），玩家的防御却随等级、成长、装备一路涨。
防御一旦超过怪的攻击，减法结果就是负数，被 `Math.max(1, …)` 按 1 处理 —— 实际上就是不掉血。

`vtest_enemy_balance` 实测（2026-09-09，穿满该图真实掉落的玩家）：

| 图 | 每刀挨打 | 被杀需几刀 |
|---|---:|---:|
| 图1 枯荣之地 | 0.0% | ∞ |
| 图5 血潮裂谷 | 0.0% | ∞ |
| 图10 腐变之源 | 0.0% | ∞ |

**10 张图里 9 张是完全免伤。** 30% 停挂回血机制因此永远不会触发。

**问题二：想调高难度，就一定会打死新手。**
把怪攻击调高到「穿装玩家有感觉」的水平，裸装玩家在高级图一场要掉 130% 血 —— 直接被打死。
实测过：怪攻击调到 692（图10）时，`vtest_early_game` 新手胜率掉到 **2.3%**，`vtest_pet_balance` 出现 **16 例死亡**。
反过来，要保证最弱的玩家不死，怪攻击最多只能到 564，那时穿装玩家 **10 场**才回一次血 —— 等于没改。

**根因**：减法公式下，同样的攻击数字打在「防御 393 的裸装」和「防御 505 的穿装」身上，效果是 3 倍以上的差距。
这两个档位在游戏里必然同时存在，所以**减法公式下「新手不死」和「老手有压力」不可能同时成立**。

## 2. 新公式

只改「攻击 vs 防御」这一层，命中、闪避、暴击、增伤、减伤、吸血**全部保持原样**。

```
第 1 步  命中判定（不变）
        命中率 = 命中 ÷ (命中 + 闪避)，钳制在 5%~95%
        没打中 → 伤害 0，可触发反击类血统被动

第 2 步  攻防对抗（★唯一改动）
        有效防御 = max(0, 防御 − 穿透)
        挡掉的比例 = 有效防御 ÷ (有效防御 + 攻击力)
        基础伤害   = 攻击力 × (1 − 挡掉的比例)
                   = 攻击力 × 攻击力 ÷ (攻击力 + 有效防御)

第 3 步  暴击（不变）
        暴击 → × 暴击伤害倍率（默认 1.5）

第 4 步  增伤 / 减伤乘区（不变）
        × (1 + 伤害加成%)
        × (1 − 受伤减免%)，减免封顶 90%

第 5 步  取整，最低 1
        最终伤害 = max(1, round(…))

第 6 步  吸血（不变）
        回复 = 伤害 × 吸血率
```

一句话记住它：

> **你的防御和对方的攻击力相等时，正好挡掉一半。防御再高也挡不完，防御再低也不会被秒。**

---

## 3. 为什么是这个形式

| 要求 | 这条公式怎么满足 |
|---|---|
| 永远不可能免伤 | 结果是除法，防御再大也只是无限接近 0，不会变成 0 |
| 不会被秒杀 | 防御为 0 时伤害 = 攻击力全额，不会放大 |
| 防御有递减，不能线性堆到无敌 | 防御翻倍 ≠ 减伤翻倍（防御 = 攻击力时挡 50%，防御 = 3 倍时挡 75%） |
| 不新增需要解释的常数 | 基准就是「对方的攻击力」本身，不需要额外的 K 表 |
| 低级图高级图自动适用 | 攻防都在式子里，量级自动缩放，不用每图单独校准 |
| 攻守对称 | 玩家打怪、怪打玩家用同一条，怪的高防御也不会让人打不动 |
| 符合「数值定死」 | 公式里没有任何随玩家成长变化的变量，仍是两张死表（怪数值 + 玩家属性）对撞 |

## 4. 验收目标

改完后，用现有工具（`vtest_enemy_balance` + `equipment_simulator`）应当跑出这样的结果：

| 玩家档位 | 一场战斗掉血 | 换算 |
|---|---:|---|
| 裸装（贫民） | 45% ~ 60% | 能连打 2 场，第 3 场触发 30% 停挂。**不会被打死** |
| 穿满该图掉落（正常） | 20% ~ 25% | **约 3 场回一次血** |
| 毕业打造 | 12% ~ 18% | 碾压感来自「杀得快少挨刀」，不是不掉血 |

另外两条硬要求：

1. **杀怪刀数基本不变** —— 现有「裸装 4~6 刀 / 正常 2.5~4 刀 / 毕业 1~2 刀」的目标继续成立，怪的 hp 表不用动。
2. **不存在任何一张图是完全免伤**（挨打严格 > 0）。

### 为什么「杀怪刀数几乎不会变」

因为量级关系不一样：

- 玩家打怪：玩家攻击（图10 约 1075）**远大于**怪防御（182）→ 新公式算出来跟减法差不多
- 怪打玩家：怪攻击（411）跟玩家防御（393~505）**是同一量级** → 变化巨大

手算校验（图10，不改任何现有数字）：

| | 旧公式 | 新公式 |
|---|---:|---:|
| 穿装杀怪刀数 | 2.82 刀 | 2.74 刀 |
| 裸装杀怪刀数 | 3.98 刀 | 3.78 刀 |
| 穿装每场掉血 | **0%** | **21%** |
| 裸装每场掉血 | 42% | **49%** |

**改动几乎全部落在生存侧，推图速度不受影响。** 这是本方案最大的好处：不用重新校准 10 张图的怪物血量。

## 5. 哪些数值要动，哪些不用

| 数值 | 要不要改 | 说明 |
|---|---|---|
| `areaEnemyStats.hp` | **不动** | 刀数基本不变 |
| `areaEnemyStats.def` | **不动** | 玩家攻击远大于它，影响极小 |
| `areaEnemyStats.atk` | 可能微调 | 新公式下伤害普遍上升，个别图（如图3 裸装算出来 73%，贴着死亡线）需按实测下调 |
| 装备词缀「防御」 | 观察 | 从线性减伤变成递减减伤，性价比会下降；先不改，实测后决定要不要调权重 |
| 受伤减免 `dr` / 穿透 `pen` | **不动** | 继续作为乘区 / 先减防御，语义不变 |

## 9. 未决问题

1. **图3 这类边界怎么调**：裸装算出来一场掉 73%，而 30% 停挂只在**场与场之间**生效，场中掉超过 70% 会真死。实施时按实测结果下调该图 `atk`，或者考虑给「血量归零」改成撤退（另议）。
