本方案逐条对照现状后给出：

| # | 手册条目 | 现状 | 处置 | 优先级 |

## 二、手册 vs 现状：差异点与调整理由（★重点）

### R1 【死锁·需你拍板】神级宠门槛 成长≥60 ↔ 只有神级宠能涅槃

- 手册 2.6：合成神级宠要求 **主宠与副宠成长值都 ≥ 60**。
- 手册 2.7：**只有神级宠才能涅槃**；涅槃才是吸收 50% 成长的主通道。
- 推论：普通宠的涨成长路径只剩「进化 +0.1~0.2/次（4 次共 +0.8）」+「合成变异 +1~3」。
  从初始成长 5 涨到 60，需要约 **25~40 次合成**（每次消耗 2 只 Lv40 宠 + 合成之石），
  而合成之石按新掉落表要图 7（Lv37+）才开始产。
- **这不是 bug，是节奏问题**：手册 2.7 自己写「60：需要长期积累」，所以逻辑自洽，但会非常慢。
- **默认处置**：按手册实装 `godPets.minGrowth = 60`，但**单独提为 config 常量**（`Config.pet.godPets.minGrowth`），
  并在合成界面显示「成长进度 X/60」长线目标条。
- **建议值（待你拍板）**：`30`。理由：手册 2.7 的节奏表「一月 20 / 三月 25」，30 ≈ 三个月硬核玩家的真实水位，
  60 会把神级宠推到「几乎见不到」。改法：`config.js` 里把 `minGrowth: 60` 改成 `30`，其余不用动。

### R2 【冲突】新手引导 G9「浴火涅槃」会卡死

- 现状：`config.drop.quests` 的 g9 是 `type:'nirvana'` 引导任务（发涅磐兽、顶到 Lv60 让玩家涅槃）。
- 手册：只有神级宠能涅槃 → 新手引导期玩家只有普通宠，**G9 永远无法完成，引导链断在最后一环**。
- **默认处置**：G9 从「涅槃」改为「**登临终阶**」（`type:'evolve'`，need 4 = 走完 5 阶最后一阶），
  文案/引导条/奖励同步改；涅槃从引导链移到主线（m19/m31 作为长线目标保留）。
  `tutorialMode.grants` 里 g9 的「涅磐兽×1」改为「传说进化素材×2」（终阶素材）。
- 理由：手册阶段1-6 只要求引导的「进化阶段触发条件」更新为 Lv10/25/40/60，没要求引导里做涅槃。

### R3 【未定义】终阶进化需要「传说进化素材 + 特殊道具」，特殊道具没定义

- **默认处置**：不新增道具（避免美术图标缺口），用 `evolution.finalExtra = { name:'传说进化素材', amount:3 }` 承载，
  即终阶 = 传说进化素材 ×(1+3)。想换成独立道具时只改这一行。

### R4 【差异】Lv40「三阶」没有新形态美术

- 手册 2.5 要求「每阶进化有外观变化」。现有形态树只有 3 层（基宠 → 一阶 → 二阶 → 终形态），
  加一层需要 16 个新形态名 + 16 张立绘，美术缺口无法在本次补齐。
- **默认处置**：5 阶 = **3 次换形态（Lv10 / Lv25 / Lv60）+ 1 次淬体阶（Lv40，形态不变、成长+）**。
  配置里标 `keepForm: true`，形态树只在 `Lv35 → Lv25` 处改一个数字，零美术成本。
- 理由：保住「5 个阶段、4 个门槛」的手册骨架，外观差异等美术到位后补（只需在 tree 里加节点）。

### R5 【差异】地图 17→10，但手册又说「图11+ = 地狱/通天塔」

- 手册 2.1 表格是 10 张图（图10 = Lv60 毕业），正文却写「图11+ = 地狱/通天塔（不在本次范围）」，自相矛盾。
- **默认处置**：按表格实装 10 张。图 11-17 的 7 张预留毕业图（本来就因 Lv60 上限进不去）连同
  主线 m41-m68、7 种区域材料、7 个世界地图点位**一并删除**；「地狱/通天塔」作为后续独立系统（不占用图编号）。
- 等级上限 `maxLevel` 保持 **60**（与手册图10 = Lv55-60 毕业完全一致，无需改）。

### R6 【差异】手册未提「淬体」与「鉴定石」

- 前者：2026-09-04 定过「后 7 次淬体」，本次按手册收敛为 4 次进化后**不再保留独立淬体通道**（避免 5 阶 + 7 淬体 = 12 次的混乱），
  淬体的成长收益合并进 Lv40 三阶（keepForm 阶，成长 +0.4，是普通阶的两倍）。
- 后者：鉴定石是现有鉴定玩法的必需品，手册没提 → **保留**（不放进手册的打造石权重表，单独一行小权重）。

### R7 【架构】服务端目前不结算宠物成长

- `config-server.mjs` 只镜像 `pet / exp / battle / regen / petTraits / bloodlinePassive`，**没有 drop、equipment、synthesize、nirvana**。
  合成与涅槃现在是「客户端算 + 直接 `updatePet`」，服务端没有任何校验点。
- **默认处置**：本次新增 `supabase/migrate_god_pet.sql`——pets 加 `evolve_stage`(int)、`is_god_pet`(bool) 两列 + 旧数据迁移 +
  两个校验 RPC（`check_god_synth` / `check_nirvana`），客户端在合成/涅槃前先调校验通过再执行。
  完整的「服务端权威结算」要重写合成/涅槃为 RPC，工作量大，列为 P2（见第七节）。
