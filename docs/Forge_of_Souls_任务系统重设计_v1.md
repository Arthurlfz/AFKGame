## 1. 现状诊断

### D1 · 生命周期错位：可重复任务混进一次性分类（最严重）

- `collect_loop` ×10 条挂在 `category:'main'`；`awaken_road` 挂在 `category:'pet'`（`config.js:649-665`）。
- `quest.js:247 isFinished()` 对 `repeatable` **永远返回 false** → `ui-quest.js:295` 的 `!q.finished` 永远为真 → 这 11 条**永远占着「主线 / 宠物」tab 与角标**。
- 后果：主线推完了没有"清空"的反馈；玩家分不清哪些是"推进度的一次性任务"、哪些是"可以无限刷的委托"。

### D2 · 日常任务与玩家进度脱节

- `d1~d12` **全都没有 `unlockLevel`**（`config.js:666-677`）→ Lv1 就全部可见。
- 但 `d7` 要「血潮凝晶 ×20」（图 5 / Lv25 材料）、`d8` 要「腐变之心 ×20」（图 10 / Lv55 材料）→ 低等级玩家列表里躺着**永远做不完的日常**。
- `d1`（击杀 100）与 `d2`（击杀 200）高度重复，缺少区分度。

### D3 · 没有「系列」概念，主线是 40 条平铺

- `m1~m40` 天然是 **10 章 × 4 环**（章 = 图：击败 → 收集 → 养成 → 装备/打造），结构完全对齐。
- 但数据里没有 `chapter` 字段，UI 只能平铺 40 条；没有任何"这一章通关了"的正反馈。

### D4 · 宠物线有分组数据却没用于展示

- `pe1~pe24` = **8 家族 × 3 环**（孵化 → 带它打 → 它进化），`petName` 就是天然家族键。
- UI 平铺 24 条，玩家看不出"这只宠我要走完整三步"。

### D5 · 两条已上线玩法在任务系统里是隐形的

- `docs/js/trial/`（资源试炼，20 层爬塔）与 `docs/js/tower/`（通天塔，30 层）**没有任何 `Quest.reportType` 调用**（全项目检索确认）。
- 结果：副本 / 塔既没有引导，也没有日常与成就入口 —— 玩家上线看到的大玩法，在任务面板里不存在。

### D6 · 上报语义只有"累加"，表达不了"最高纪录"

- `quest.js:345 reportType(type, amount, ctx)` 只做 `progress[q.id] += amount`。
- 「爬到第几层」「觉醒第几只」这类目标要的是 **max** 而不是 sum，当前无法表达。
- 现在没有这类任务所以没暴露；一旦要接副本 / 塔，必须先补 `mode:'max'`。

### D7 · 奖励里有"死值"

- 涅槃已道具化：唯一消耗品 = **涅槃丹**（`pet_merge.js:193`、`ui-pet-merge.js:73`），**「涅磐兽」已退役**（只保留掉落与交易，无任何消耗口）。
- 但仍有 **9 条任务在发涅磐兽**：`m11 m19 m23 m29 m31 m33 m37`、`pe24`、`a3`。
- 玩家做主线拿到一堆用不上的东西 → 等于奖励缩水，且违反了归属表「任务只补当前缺口」的意图。

### D8 · 展示层信息密度不均

- `ui-quest.js:28` 的 `CATS` 有 6 个 tab：新手 / 主线 / 日常 / 成就 / 宠物 / 已完成。
- tab 角标 = **未完成数**（`ui-quest.js:271`），不分"可提交"和"没开始" → 玩家要逐个点开才知道有没有奖可领。
- 「已完成」把一次性完成和当天日常混在一起；日常每天刷完就淹没在列表里。

### D9 · 重置规则靠字段缺省猜，没有稳定位置

- 现在靠两个字段表达三种语义：`repeat`（每日）/ `repeatable`（永不结束）/ 都不写（一次性）。
- `isFinished()` 用两个分支硬编码（`quest.js:247`）。想加第四种（周常 / 赛季）没有位置。

## 2. 设计目标与原则

**目标**

1. **一个任务只属于一个 tab**。口径唯一，玩家一眼知道"我现在为什么要做它"。
2. **生命周期写成显式字段**，不再靠"有没有 `repeat` 字段"推断。
3. **分类 = 玩家的行动意图**，不是系统模块名（所以不按"装备相关 / 市场相关"切）。
4. **内容零丢失**：109 条一条不少，只搬家 + 加字段。
5. **新增能力一律标注**，不默认落地。

**原则（沿用项目既有铁律）**

- `quest.js` 的**提交幂等 / 记账先行 / 写串行 / 落盘才返回**四条骨架不动。
- 加任务仍然只改 config，不改逻辑。
- 奖励归属不破《资源归属矩阵现状.md》三条规则。
- 能从 config 派生的展示一律派生，不写第二份（例如宠物家族 = 从 `petName` 派生，不新增 `family` 字段）。

## 3. 核心模型：两个正交维度

现在的问题是把两个维度混在一张表里。拆开后一切都能归位。

### 维度 A · 任务结构 `kind`（决定生命周期 / 重置 / 入口 tab）

一个任务**只能属于一个 kind**。kind 回答"这个任务什么时候出现、会不会重来"。

### 维度 B · 目标形式 `type`（决定进度怎么算、从哪上报）

`type` 回答"进度从哪里来"。它**跨 kind 复用**：同一条"收集 50 个枯荣种荚"可以是系列里的一次性环，也可以是委托里的循环，还可以是每日的第 3 条。

> **为什么用户点名的「收集任务」不是独立 kind**：
> 收集在系列里是**一次性**（交完 `completed`）、在委托里是**循环**（交完归零重来）、在每日里是**当天**（次日清零）。
> 硬拆一个「收集」tab，等于把同一种玩家行为切成三处显示，反而更乱。
> 落地办法：**收集作为跨分类标签 + 筛选项**（见 §9.4）。若坚持要独立 tab，只需加一条 `type:'collect'` 的前缀筛选（一行 config），不影响结构。

## 4. 六大分类定义（核心表）

排序 = **注意力优先级**：被引导的 → 推进度的 → 正在养的 → 今天该做的 → 可以刷的 → 长期冲的 → 归档。

| # | `kind` | 中文 | 一句话定义 | 出现条件 | 重置 | 现状条数 |
|---|---|---|---|---|---|---|
| 1 | `guide` | 🌱 引导 | 新手线性链，一环套一环 | 上一条完成 | 不重置 | 6 |
| 2 | `series` | 📜 系列 | 按**图**分章的推进主线，每章 4 环 | 等级 / 图段解锁 | 不重置 | 50 |
| 3 | `pet` | 🐾 宠物 | 单只宠的养成三环（孵化 / 带它打 / 它进化） | 该宠所在图段等级 | 不重置 | 24 |
| 4 | `daily` | 🔁 每日 | 每天刷新的短任务 | 等级 + 当天未交 | **每日 00:00** | 12 |
| 5 | `loop` | ♻️ 循环 | 提交制循环，交完立刻重来 | 该图守关 Boss 首通 | 交完即时归零 | 11 |
| 6 | `achieve` | 🏆 成就 | 长期累计，一次性，永不清零 | 全局可见 | 永不重置 | 6 |
| — | `done` | ✅ 已完成 | **视图不是分类**：汇总所有 `finished` | — | — | — |

条数对账：50 + 24 + 11 = 85（原 `main` 60 + `pet` 25 = 85 ✔）。

### 4.1 `guide` 引导

| 项 | 内容 |
|---|---|
| **定义** | 新手 N1~N6 线性链，`requires` 前置依赖，自动接取，不可放弃 |
| **触发条件** | 无前置的 n1 自动接取；n2~n6 需上一条 `completed`。`isGuide:true` 的才进引导条 |
| **目标** | `kill 3`（n1）、`equip 1`（n2）、`craft action:reforge 1`（n3）、`evolve minLevel:10 1`（n4）、`disposeKill`（n5）、`direction`（n6） |
| **奖励** | `reward` 字段**一律为空**；发放走 `tutorialMode.supplyBox` 钥匙表（奖励即钥匙，幂等自愈，账本 `keys:{taskId}` 只发一次） |
| **重置规则** | 不重置。唯一出口 = 完成后逐条推进；或玩家点「跳过引导」一次性全标完成（`Quest.skipGuide()`） |
| **展示** | ① 顶部**常驻引导条**（不属于抽屉）：当前 1 条 + 「现在：/ 为什么：」文案 + 「去 XX」跳转 + 「补钥匙」+ 「跳过」；② 抽屉「引导」tab 看全链进度 |

### 4.2 `series` 系列（原「主线」改名 + 分章）

| 项 | 内容 |
|---|---|
| **定义** | 按**图**分章的推进主线。每章固定 4 环：**击败（本图怪）→ 收集（本图专属材料）→ 养成（进化/涅槃/合成/孵化）→ 装备（装备/打造/分解）** |
| **触发条件** | 按 `unlockLevel` 解锁（必须与该图 `levelRange` 对齐，现状已对齐）；章内 4 环**并列**，可任意顺序做 |
| **目标** | 现有 `kill / collect / evolve / nirvana / synth / hatch / craft / salvage / equipDrop`，另含 10 条 `boss`（守关 Boss 首通） |
| **奖励** | 该章图档的打造通货 + 当前阶段的进化素材（≤2/条传说）。**禁止**跨阶段发资源 |
| **重置规则** | 不重置，一次性 |
| **展示** | **按章折叠**：章头 = 图名 + 缩略图 + `x/4` 进度条；展开 = 4 张任务卡。未解锁的章灰显并显示解锁等级 |

> **新增（需拍板）**：章完成奖励（章宝箱）。10 章各给一次，奖励 = 该章图档的打造通货，不给下一章的资源（防跳章白嫖）。

### 4.3 `pet` 宠物养成

| 项 | 内容 |
|---|---|
| **定义** | 8 个家族 × 3 环：**孵化它 → 带它打 → 它进化** |
| **触发条件** | 按 `unlockLevel`（腐噜兽 1 → 幽影兔 43，与家族所在图段对齐）。没这只宠也能看到（提前立目标） |
| **目标** | `hatch petName`（已拥有即 1/1 完成，避免开局宠卡死）、`kill petName need`（**只算该宠出战**）、`evolve petName 1` |
| **奖励** | 孵化给进化素材（练宠燃料）/ 试炼给进化素材 / 进化给打造通货；每条固定经验 600 |
| **重置规则** | 不重置，一次性 |
| **展示** | **按家族折叠**：家族头 = 宠物头像 + 名字 + `x/3`。家族键**从 `petName` 派生**，不新增字段 |

### 4.4 `daily` 每日

| 项 | 内容 |
|---|---|
| **定义** | 每天 00:00（本地）刷新、当天可交一次的短任务 |
| **触发条件** | 等级解锁 **+ 当天未交**。上下线 / 跨天都会触发 `ensureDailyReset()` |
| **目标** | 通用动作（击杀 / 打造 / 分解 / 成交）+ 阶段收集（本图材料） |
| **奖励** | **只发打造通货 + 经验**（铁律 1）。绝不发进化 / 涅槃 / 传说道具 |
| **重置规则** | `dailyDate !== today` → 清 `dailyDone` 并把所有 `repeat` 条目的 `progress` 归零，然后落盘 |
| **展示** | tab 角标 = 今日**可提交数**（红点）。已交的当天沉到列表底部并灰显，不消失（让玩家知道今天做过什么） |

**建议修正（需拍板，P0）**：现有 12 条按「4 固定 + 2 阶段轮换」重排，见 §11 分期表。

### 4.5 `loop` 委托（循环）

| 项 | 内容 |
|---|---|
| **定义** | 提交制循环：攒够材料 → 交 → 立刻归零重新累计 |
| **触发条件** | **该图守关 Boss 首通**（`isAreaCleared(area)`，读的是 `boss{n}` 任务的完成态）。所以每图解锁 1 条 |
| **目标** | `collect_loop`：进度 = **背包中该材料的实时持有量**（`Materials.getQuantity`），提交时扣除 `need` |
| **奖励** | 打造通货（随图阶递进）+ 经验 + **资源试炼门票 ×1**（`trial-config.js:109` 注入）。禁止进化 / 涅槃材料（铁律 1） |
| **重置规则** | 不按日期。交完立刻把 `progress` 归零 —— 因为进度读背包、提交又扣材料，天然循环 |
| **展示** | 单独 tab「委托」。**必须从 `main` / `pet` 分类移出**，这是收拾混乱的头号动作。卡片常显「已完成 x 轮」计数（需新增，见 §10） |

**另含 1 条长线**：`awaken_road`（觉醒之路）从 `pet` 移入本类 —— 它是 `repeatable` 的提交制收集（图 1~10 材料每种 888 → 觉醒石），语义与委托完全一致，只是量级不同。

### 4.6 `achieve` 成就

| 项 | 内容 |
|---|---|
| **定义** | 长期累计、一次性、永不清零 |
| **触发条件** | 全局可见（现状无 `unlockLevel`）。**建议**给远期成就加 `unlockLevel` 或按时长隐藏，免得 Lv1 玩家一进游戏就看到「击杀 10000」 |
| **目标** | `kill 10000` / `evolve 50` / `nirvana 20` / `synth 20` / `hatch 50` / `craft 100` |
| **奖励** | 唯一允许发高稀有度道具的类别（不可重复领）。**必须修**：`a3` 发的是已退役的涅磐兽 |
| **重置规则** | 永不。`completeQuest` 里 `category !== 'achieve'` 才清零 `progress`（`quest.js:503`），成就保留累计战绩 |
| **展示** | 卡片带进度百分比条 + 「还需 N」。建议加 `tier`（铜 / 银 / 金）用于视觉分档（见 §10） |

### 6.2 `reportType` 必须补 `mode`（技术前置）

现状只支持累加。上面两张表里「爬到第几层」「觉醒第几只」要的是**最高纪录**。建议：

```js
// quest.js
function reportType(type, amount, ctx) { ... }
// ctx 增加 mode: 'add'（默认） | 'max'
```
