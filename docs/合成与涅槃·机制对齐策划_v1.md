## 一、问题（大白话）

原版让人上瘾的是**老玩法里有惊喜和讲究**：



* 原版**合神**是赌：50cc 起有概率成神、平均 100cc 成、300cc 必成 ——"这一合能不能成神" 是心跳。

* 原版**涅槃**有讲究：副宠练得越高级（130 级），喂给主宠吃得越多 —— 养副宠本身是玩法。

Forge 抄了名字和形状，但两处都是 "死" 的：

### 死钩子 1：合成变异概率 50%，变异不稀罕

现状：`mutation.chance = 0.5`，变异概率固定 50%，变异成长 +1\~3。

问题：



* **50% 太频繁**，变异成了家常便饭，没有 "大奖" 的心跳；

* 概率**不跟主宠成长挂钩**，没有 "宠物越强越容易出好货" 的成长感（原版：cc 越高成神概率越高）。

### 死钩子 2：涅槃的副宠等级加成永远是 0

现状：`nirvana.levelBonus = 0.01`，注释写着 "练得越高当肥料越值钱"。

问题：



* 宠物**等级上限 = 60**，涅槃门槛 = 60 → 副宠永远 60 级 → `(副宠等级 - 60) × 0.01 = 0`，**这个加成永远吃不到**；

* 玩家发现 "副宠练到 60 级和随便抓一只，喂出来一样"，副宠养成线整个是空的。

## 二、改动 1：合成变异 →「大奖制」（对齐原版 "合神成神"）

### 2.1 规则



| 档位               | 触发                | 效果                                     |
| ---------------- | ----------------- | -------------------------------------- |
| 普通合成             | 每次合成              | 新宠成长 = 主 ×60% + 副 ×40%（不变）             |
| **普通变异**（・异变）    | 按主宠成长 roll 概率（下表） | 成长再 +1\~3，出「・异变」宠                      |
| **史诗变异**（・异变・暴走） | 普通变异命中后再 roll 15% | 成长再 **+5\~10** + 必送 1 条 T1 特质 + 全屏弹窗特效 |

### 2.2 变异概率表（按主宠成长分档，对齐原版 "50cc 起赌 / 300cc 必成"）



| 主宠成长   | 变异概率         | 史诗变异总概率（×15%） |
| ------ | ------------ | ------------- |
| 0\~14  | 10%          | 1.5%          |
| 15\~29 | 20%          | 3.0%          |
| 30\~49 | 35%          | 5.25%         |
| 50\~79 | 55%          | 8.25%         |
| 80\~99 | 75%          | 11.25%        |
| ≥100   | **100% 必变异** | 15%           |



* 低成长合宠偶尔爆个奖 → 新手期有盼头；

* 高成长必变异 + 15% 史诗 → 毕业宠互合也有持续心跳；

* **≥100 必变异** = 对齐原版 "300cc 必成神"。

### 2.3 衔接高成长系统（顺带解锁）

`calcSynthesizeGrowth` 没有 maxGrowth 限制 → 史诗变异（+5\~10）可以让合成结果**突破成长 100**，正好成为你未完成方案《高成长系统》（成长果破 100）的**第二条破 100 途径**。方案落地时此项免费生效。

### 2.4 配置（落 config.js）



```
synthesize: {

&#x20; minLevel: 40,

&#x20; material: { name: '合成之石', amount: 1 },

&#x20; mainW: 0.6,

&#x20; subW: 0.4,

&#x20; mutation: {

&#x20;   // 按主宠成长分档：低成长少见、高成长必出（对齐原版 50cc 起赌 / 300cc 必成）

&#x20;   chanceByGrowth: \[

&#x20;     { min: 0,   chance: 0.10 },

&#x20;     { min: 15,  chance: 0.20 },

&#x20;     { min: 30,  chance: 0.35 },

&#x20;     { min: 50,  chance: 0.55 },

&#x20;     { min: 80,  chance: 0.75 },

&#x20;     { min: 100, chance: 1.0 }

&#x20;   ],

&#x20;   growthBonus: \[1, 3],                 // 普通变异（沿用）

&#x20;   epic: { chance: 0.15, growthBonus: \[5, 10], grantT1Trait: true }  // 史诗变异

&#x20; }

}
```

### 2.5 代码改动点



* `pet_merge.js`：`rollMutation(cfg)` 改为按主宠成长查表（新函数 `rollMutationByGrowth(cfg, mainGrowth)`）；新增 `rollEpicMutation`；`calcSynthesizeGrowth` 支持 epic 分支；

* 变异成功特效：沿用现有弹窗，史诗变异加全屏流光 / 音效（ui-pet-synth.js）；

* 合成预览面板：显示 "变异概率 X%（史诗 Y%）"—— 让玩家在按按钮前就看见赌注。

## 三、改动 2：涅槃 →「肥力制」（对齐原版 "130 级副宠"）

### 3.1 规则



* **副宠 60 级后**，溢出经验不再只凝凝魂晶石，同时给**副宠自己攒 "肥力"**（宠物级字段，跟凝魂晶石同源同节奏）；

* 涅槃时按副宠肥力**加吸收率**：0 肥力 = 50% 吸收（现状），满肥力 = **100% 吸收**；

* 副宠被吃 → 肥力随副宠消失；主宠涅槃重置等级 → 主宠肥力清零（重新攒）。

### 3.2 数值表



| 项     | 值                          | 说明                         |
| ----- | -------------------------- | -------------------------- |
| 肥力转化  | 每 12000 溢出经验 = 1 点         | 与凝魂晶石 perCrystal 同值，玩家一眼就懂 |
| 肥力上限  | 40 点（≈48 万经验）              | 对应凝魂晶石 40 颗的挂机时长           |
| 每点加吸收 | +2.5%（0.025）               | 满肥力 +100%                  |
| 满肥力吸收 | 50% × (1 + 1.0) = **100%** | 封顶，不膨胀                     |

### 3.3 收益对比（可复算）

副宠成长 40，主宠成长 50（未过 60 分水岭）：



| 副宠状态          | 吸收成长    | 涅槃后主宠  |
| ------------- | ------- | ------ |
| 60 级 0 肥力（现状） | +20     | 70     |
| 60 级满肥力       | **+40** | **90** |

副宠成长 50，主宠成长 70（过 60 分水岭，减半）：



| 副宠状态 | 吸收成长    | 涅槃后主宠  |
| ---- | ------- | ------ |
| 0 肥力 | +12.5   | 82.5   |
| 满肥力  | **+25** | **95** |

> 验证：40×0.5×1.0=20｜40×0.5×2.0=40｜50×0.5×1.0×0.5=12.5｜50×0.5×2.0×0.5=25

### 3.4 为什么选 "肥力" 而不是放开等级

原版靠 "副宠 130 级" 实现，但 Forge 宠物等级上限 60 = 涅槃门槛 60，**放开等级会撕开全系统对齐链**（config 注释反复强调 60 是硬锚）。肥力制：



* 用**已有的溢出经验机制**（凝魂晶石同款）替代等级，不改等级上限、不动对齐链；

* 玩家心智一致："练满的宠继续挂 = 攒资源"，只是这次资源存在宠物身上、喂掉更值钱；

* 副宠从 "随便抓一只" 变成 "要养肥的鸡"，副宠养成线重新活了。

### 3.5 配置（落 config.js）



```
nirvana: {

&#x20; minLevel: 60,

&#x20; absorbRatio: 0.5,

&#x20; // ❌ levelBonus: 0.01 删除（死钩子，maxLevel=60 永远吃不到）

&#x20; fatness: {

&#x20;   perExp: 12000,           // 副宠 60 级后每 12000 溢出经验 = 1 点肥力（与凝魂晶石同源）

&#x20;   maxFatness: 40,          // 上限 40 点（≈48 万经验）

&#x20;   absorbPerFatness: 0.025, // 每点 +2.5% 吸收 → 满肥力 = 50% × (1+1.0) = 100%

&#x20; },

&#x20; subGrowthRatio: 0.5,

&#x20; lowGrowthPenalty: 0.2,

&#x20; growthCap: 60,

&#x20; capRatio: 0.5,

&#x20; material: { name: '涅磐兽', amount: 1 },

&#x20; crystalBonus: { material: '凝魂晶石', amount: 10, absorbBonus: 0.3 },

&#x20; resetLevel: true,

&#x20; maxGrowth: 100

}
```

### 3.6 代码改动点



* `pet.js`：宠物对象加 `fatness` 字段；60 级溢出经验结算处（battle-settle /idle-bridge/expPool 同款逻辑）加 "副宠候选攒肥力" 分支；

* `pet_merge.js`：`calcNirvanaGrowth(main, sub, bonusMult)` 的 `lvBonus` 改为读 `sub.fatness` → `1 + fatness × absorbPerFatness`；

* `nirvanaInner`：扣副宠前把 fatness 一并结算；主宠涅槃后 `main.fatness = 0`；

* 涅槃预览面板：显示 "副宠肥力 23/40 → 本次吸收 79%"—— 让玩家看见 "养肥值不值"；

* 副宠资料页 / 兽栏：显示肥力条。

## 四、不动的东西（边界）



1. **觉醒系统（awaken）不动**—— 它是 Lv60 毕业奖励（技能 +20% + 血统加成），跟本次改动正交；

2. **掉落保底**不加（宪法 D3）；

3. **品级 / 属性膨胀**不加（宪法 D4）：肥力制有 100% 吸收封顶、成长软上限 100 仍在、60 分水岭减半仍在；

4. **等级上限 60 / 对齐链**不动（涅槃门槛 = 毕业图顶点 = 等级上限）；

5. **成长值只做门槛**的宪法条款暂不触碰 —— 本次只调 "合成变异概率" 和 "涅槃吸收率"，不改变 "成长值高 → 数值放大" 的关系。
