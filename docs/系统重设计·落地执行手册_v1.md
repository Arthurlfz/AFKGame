## 一、项目背景与当前状态

### 1.1 项目概述
Forge of Souls 是一款单人挂机游戏，核心循环：挂机→掉落→打造装备→合成宠物→变强→推图→地狱/通天塔。当前问题：成长值膨胀太快（玩家一天成长15）、装备掉落废品多、怪物数值有崩点（图9/10穿装2.42刀）、宠物进化阶段少（3阶）、缺少神级宠系统。

### 1.2 关键文件路径
| 系统 | 文件路径 | 说明 |
|---|---|---|
| 核心配置 | `docs/js/core/config.js` | 所有数值配置（怪物/装备/掉落/宠物/进化/合成/涅槃） |
| 服务器配置 | `supabase/functions/_shared/config-server.mjs` | 服务器端配置副本（双份维护铁律，改config.js必须同步改这个） |
| 宠物核心 | `docs/js/pet/pet.js` | 宠物属性计算、进化、血脉特质 |
| 宠物合成/涅槃 | `docs/js/pet/pet_merge.js` | 合成（synthesize）+涅槃（nirvana）逻辑 |
| 装备核心 | `docs/js/equipment/equipment.js` | 装备属性计算（getEquipBonuses在318行） |
| 装备打造 | `docs/js/equipment/equipment_craft.js` | 重铸/增缀/剥离/神圣石打造 |
| 怪物数据 | `supabase/functions/_shared/enemy-data-server.mjs` | 怪物数据表（自动生成，勿手改） |
| 平衡测试 | `docs/tests/vtest_enemy_balance.js` | 怪物平衡测试（当前FAIL：图9/10穿装2.42刀） |
| 掉落测试 | `docs/tests/vtest_drop.js` | 掉落测试 |
| 任务测试 | `docs/tests/vtest_quest.js` | 任务测试（140条断言） |
| 结算函数 | `supabase/functions/battle-settle/index.ts` | 服务器端战斗结算（Edge Function） |

### 1.3 双份维护铁律
改 `docs/js/core/config.js` 的任何数值，**必须同步改** `supabase/functions/_shared/config-server.mjs`。两个文件必须保持一致，否则前端显示和服务器结算会不一致。

### 2.6 神级宠系统（核心新系统）

**决策**：神级宠是单独的宠物（不是普通宠变的），有自己的名字/外观，成长系数+50%，只有神级宠才能涅槃。

**获得门槛**：
- 主宠和副宠都必须是**终阶**（进化5阶）
- 主宠和副宠的**成长值都必须≥60**
- 消耗合成之石

**获得方式**：
- 合成时**30%概率**出神级宠
- 有**涅槃丹**时**100%**出神级宠
- 神级宠是单独的宠物（有自己的名字、icon、基础属性），不是普通宠的进阶形态

**涅槃丹获得**：
- BOSS掉落（每图Boss有概率掉）
- 任务奖励（主线任务/成就）
- 循环任务兑换（用区域材料+打造石兑换）

**神级宠特性**：
- 成长系数（statCoeff）**+50%**（比普通终阶宠强一半）
- **只有神级宠才能涅槃**（叠成长）
- 有几个特定的神级宠（不是每种普通宠都有神级形态）
- 外观独特（icon不同）

**神级宠出生成长值处理（方案C：成神上限60+超过部分折算加成）**：
- **基础计算公式**：
  - 基础成长 = 主宠×0.6 + 副宠×0.4
  - 神级加成 = +2~5（比普通变异+1~3高，因为神级宠更稀有）
  - 涅槃丹加成 = +5~10（有涅槃丹时额外加）
  - 计算结果 = 基础成长 + 神级加成 + 涅槃丹加成
- **成神上限60（满神）**：
  - 神级宠出生时成长值上限为60
  - 如果计算结果 > 60，出生成长值取60
  - 超过60的部分 = 计算结果 - 60
- **超过部分折算加成**：
  - 超过部分每1点，折算成 statCoeff 额外 +1%
  - 上限：超过部分最多折算 +20%（即计算结果最多80，超过80的部分不再折算）
  - 神级宠最终 statCoeff = 普通终阶×1.5（基础神级加成）+ 超过部分折算（最多+20%）= 最多×1.7
  - 示例：主宠成长65、副宠成长70，基础成长=65×0.6+70×0.4=39+28=67，神级加成+3=70，超过60的部分=10，statCoeff额外+10%，最终statCoeff=普通×1.5×1.1=普通×1.65
- **设计意图**：
  - 跟原版对齐：成神后最高60cc（满神）
  - 鼓励玩家用高成长副宠合成：超过越多，statCoeff加成越多
  - 超过部分不浪费：折算成永久属性加成
  - 神级宠出生不会太强（上限60），但高成长素材合成的神级宠 statCoeff 更高
  - 涅槃可以突破60上限（叠成长是长线追求）

**实施要点**：
- 在 `config.js` 的 `pet` 段新增 `godPets` 配置，定义神级宠列表（名字、icon、baseHp/baseAtk/baseDef、statCoeff）
- 神级宠的 statCoeff = 对应普通宠终阶的 statCoeff × 1.5
- 修改 `docs/js/pet/pet_merge.js` 的合成逻辑（synthesize）：
  - 加阶段检查：主宠和副宠都必须是终阶（evolveStage === 5）
  - 加成长值检查：主宠和副宠成长值都必须≥60
  - 加神级宠判定：30%概率出神级宠，有涅槃丹时100%
  - 神级宠出生成长值计算（方案C）：
    - 基础成长 = 主×0.6 + 副×0.4
    - 神级加成 = +2~5（随机）
    - 涅槃丹加成 = +5~10（有涅槃丹时）
    - 计算结果 = 基础 + 神级加成 + 涅槃丹加成
    - 出生成长值 = min(计算结果, 60)（成神上限60）
    - 超过部分 = max(0, 计算结果 - 60)
    - statCoeff额外加成 = min(超过部分×1%, 20%)（每超过1点+1%，上限+20%）
    - 最终statCoeff = 普通终阶×1.5 × (1 + statCoeff额外加成)
- 新增道具"涅槃丹"（在 `config.js` 的 items/materials 里加）
- 涅槃丹掉落：加进 BOSS 掉落表、任务奖励、循环任务兑换
- 修改 `docs/js/pet/pet.js`，支持神级宠类型（isGodPet 标记）
- 神级宠在UI上有特殊标识（金色边框/特殊icon）
- **只有神级宠才能涅槃**：在涅槃逻辑里加 isGodPet 检查

### 2.7 涅槃/成长值调整

**决策**：只有神级宠才能涅槃，涅槃吸收50%不衰减，用涅磐兽消耗控制节奏。

**涅槃规则**：
- **只有神级宠才能涅槃**（普通宠/终阶宠都不能涅槃）
- 涅槃吸收比例：**50%**（副宠成长值的50%加到主宠）
- **不衰减**（没有"成长越高吸收越低"的机制）
- 涅磐兽消耗：从1个提高到**5-10个**（用材料消耗控制节奏，不是衰减）
- 主宠等级重置为1（重新练级）
- 副宠消失

**成长值长线目标**：
- 初始宠成长值：5
- 玩家需要把成长值叠到**60**才能合成神级宠（长线目标）
- 神级宠出生后可以涅槃叠更高成长（没有硬上限，永远能涨）
- 节奏目标（用模拟器验证，不是拍脑袋）：
  - 一天：成长涨到10左右（有爽感）
  - 一周：成长15（开始慢）
  - 一个月：成长20（长线追求）
  - 三个月：成长25（硬核目标）
  - 60：需要长期积累（合成神级宠的门槛）

**实施要点**：
- 修改 `config.js` 的 `nirvana` 段：
  - 加 `requireGodPet: true`（只有神级宠能涅槃）
  - `absorbRatio: 0.5`（保持50%）
  - 去掉衰减机制（如果有的话）
  - `material.amount: 5`（从1提高到5，或按阶段5-10）
- 修改 `docs/js/pet/pet_merge.js` 的涅槃逻辑（nirvana）：
  - 加 isGodPet 检查
  - 调整涅磐兽消耗
- 成长值获取速度调整：
  - 进化每次+0.1~0.2（保持）
  - 合成变异加成+1~3（保持）
  - 涅槃吸收50%（保持）
  - **用涅磐兽消耗（5-10个）控制涅槃频率，从而控制成长值获取速度**
- 写成长值获取模拟器，验证一天/一周/一个月能涨多少，根据结果微调涅磐兽消耗
- 硬上限 maxGrowth 保持100（或去掉，永远能涨）

## 六、Anti-Pattern（绝对不能做的事）

### 6.1 数值相关
- ❌ **禁止拍脑袋定数值**：所有怪物数值必须用装备模拟器校准，所有成长值节奏必须用成长值模拟器验证
- ❌ **禁止只改前端不改服务器**：改 `config.js` 必须同步改 `config-server.mjs`（双份维护铁律）
- ❌ **禁止用 atk×1.3 简化假设做平衡测试**：必须用实际装备模拟器
- ❌ **禁止硬编码数值**：所有可配置数值必须放在 `config.js`，不能写死在代码里

### 6.2 系统设计相关
- ❌ **禁止给普通宠开放涅槃**：只有神级宠才能涅槃
- ❌ **禁止给涅槃加衰减机制**：用涅磐兽消耗控制节奏，不是"成长越高吸收越低"
- ❌ **禁止神级宠是普通宠的进阶形态**：神级宠是单独的宠物，有自己的名字/外观/基础属性
- ❌ **禁止降低进化成长提升**：进化每次+0.1~0.2，成长质变交给合成/涅槃
- ❌ **禁止跳过阶段检查**：合成神级宠必须检查主副宠都终阶+成长≥60

### 6.3 代码架构相关
- ❌ **禁止破坏三层隔离**：配置层（config.js）→ 逻辑层（pet.js/equipment.js）→ UI层，不能混
- ❌ **禁止手改 enemy-data-server.mjs**：这个文件是自动生成的，改了会被覆盖
- ❌ **禁止删除已有功能**：只能新增/修改，不能删除玩家已有的功能（除非明确要求）
- ❌ **禁止不写测试**：每个新功能必须有单元测试
- ❌ **禁止一次性改太多**：按阶段落地，每个阶段完成后测试通过再进入下一阶段
- ❌ **禁止只改配置不改UI**：所有配置改动必须同步改对应的UI/hover/tooltip，否则页面显示和实际配置对不上
- ❌ **禁止硬编码UI文本**：所有显示文本（阶段名、门槛提示、物品描述）必须从配置读取，不能写死在UI代码里

### 6.4 部署相关
- ❌ **禁止只部署前端不部署Edge Function**：如果改了服务器配置，必须重新部署 battle-settle
- ❌ **禁止跳过 migrate SQL**：如果改了数据库结构（比如加列），必须跑 migrate
- ❌ **禁止不验证就提交**：所有测试通过+手动测试后才能git提交
- ❌ **禁止只改前端配置不改服务器配置**：config.js 和 config-server.mjs 必须双份一致，否则前端显示和服务器结算不一致
- ❌ **禁止客户端信任校验**：所有关键校验（神级宠合成门槛、涅槃is_god_pet、地图ID范围）必须在服务器端也做一遍，防止客户端作弊
- ❌ **禁止不备份就跑migration**：跑migration前必须备份数据库，防止数据丢失
