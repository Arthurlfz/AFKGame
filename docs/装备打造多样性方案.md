# 装备打造系统 · 通货与词缀多样性策划意见

> 基于《游戏设计理念 v2》《游戏数据地图 v1》及 `config.js / equipment.js / equipment_craft.js / ui-craft.js / salvage.js / market_bot.js` 的现有实现，针对"通货打造多样性"和"词缀多样性"卡点给出可落地方案。

## 一、现状还原（先看清底座）

**词缀结构**：`eq.affixes = { prefix:[], suffix:[] }`，每桶最多 3、总共最多 6。每条 `{type, label, tier, value}`。
- 词缀池仅 **6 种**：前缀 `攻击/生命/防御`，后缀 `速度/暴击率/吸血`。全是"数值型 % 加成"，无互动、无条件效果。
- **稀有度决定词缀条数**：白 1 / 蓝 1~2 / 金 2~3（可用增缀石补到 6）。
- T 阶（T1~T5）只决定该词缀数值区间，T1 最强。

**四种通货（全部"随机"）**：
| 通货 | 现在的作用 | 痛点 |
|---|---|---|
| 强化石 | 随机挑 1 条非 T1 词缀，T 阶 +1 | 不能选哪条，纯赌 |
| 祝福石 | 随机替换 1 条词缀类型（T 阶保留） | 不能选替换哪条/换成什么 |
| 神圣石 | 重 Roll 全部词缀数值（类型/T 阶不变） | 全赌，无法定点微调 |
| 增缀石 | 按"前缀优先→后缀"新增 1 条随机词缀 | 新增 T 阶 1~5 随机，可能是废条 |

## 二、卡点的根因（设计视角）

1. **词缀"种类"少远比"数量"少更致命**：6 个全是数值 dial，build 必然收敛到"攻击%+暴击+吸血"，没有 build 差异。
2. **四种通货"味道"雷同**：本质都是"掷骰改词缀"，玩家做的是"赌"，不是"造"。缺一块真正的决策维度（定点 / 锁定 / 剥离 / 升阶）。
3. **零玩家意图（Agency）**：所有石头都随机命中目标，玩家无法表达"我要把那条不好的换掉"，这是"卡住"的核心——不是内容少，是**可控性为零**。

## 三、词缀多样性（怎么扩）

**A. 在现有 6 类基础上加入"质变型"词缀（建议新增，仍走 prefix/suffix 桶）：**
- 进攻：`暴击伤害%(critDmg)`、`穿透%(pen)`、`攻速加成`(现为速度，可细化)
- 防御：`格挡%(block)`、`反伤%(thorns)`
- 资源：`经验加成%(exp)`、`材料掉率%(drop)`

> 注意：新增的 critDmg / pen / block / dodge 需要 `battle.js` 的属性结算支持（`getEquipBonuses` 当前只吐 `{flat,pct}`，需扩字段）。旧装备 `fromCloud` 已做脏数据兜底，向后兼容无风险。

**B. 放宽桶结构**（可选）：把"前缀≤3、后缀≤3"的硬边界改为"总条数上限 6，桶自由分配"，让"双攻击+单防御"或"纯后缀流派"成为可能，组合空间直接翻倍。

**C. 词缀联动（让"build"成立）**：例如同时带 `暴击率`+`暴击伤害` 时，额外 +X% 协同加成；或"每有 1 条后缀，前缀数值 +a%"。用纯机制、集中进 `config.js`，不新增表。

## 四、通货多样性（让每颗石头都"不一样"）

核心思路：**给玩家"选择对象"的能力**，把"随机"改成"定向 + 随机结果"。

| 通货 | 建议改法 | 玩家获得的能力 |
|---|---|---|
| 强化石 | **改成玩家点选要强化的那条词缀**（仍随机升 1 阶） | 定点提升，不再瞎赌 |
| 祝福石 | **点选要替换的某条**，类型随机（保留 T 阶） | 能"定向清理"废词条 |
| 神圣石 | 增加"单条重 Roll"模式（全部/单条） | 微调而非全押 |
| 增缀石 | 新增 T 阶按"当前稀有度档"随机（不再 1~5 全区间），避免出废条 | 补条更可用 |
| **新增·剥离石** | 删除玩家点选的 1 条词缀 | 能"洗掉"坏词条，开启"洗-补"循环 |
| **新增·固着符** | 锁定 1 条词缀，使其不被祝福/重 Roll 影响 | 保住好词条再赌其他 |
| **新增·蜕变石** | 提升装备稀有度（白→蓝→金），并解锁更多词缀槽 | 作为终极 sink，拉升交易价值 |

→ 经典组合玩法自然涌现：**补满词条 → 锁定核心词条 → 重 Roll/祝福洗其余 → 升阶拔高稀有度 → 强化到 T1**。这是有"决策"的打造，不是赌博。

## 五、落地注意 / 风险

- **战斗结算**：新增 critDmg/pen/block/dodge 必须同步改 `battle.js`，否则词缀好看但不生效。
- **测试联动**：`vtest_affix.js` / `v,test_augment.js` 硬编码了 6 类型与 `PREFIX_TYPES/SUFFIX_TYPES`，词缀池改动后必须同步改这两套测试（或用配置读取，别 hardcode）。
- **数值平衡**：升阶石/蜕变石是强通货，掉率与分解产出要重新配（现 `salvage` 只产强化/祝福），避免通胀。
- **UI**：定向强化/锁定需要 `ui-craft.js` 增加"点选某条词缀"的交互（弹层或行内选择），不是只靠现在的整面板按钮。
