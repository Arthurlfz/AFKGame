- **痛点**（用户原话）：「每一次进化解锁不了新的东西，没有新意」。
- **最终方案**（推翻了我先提的"砍到 3 次"）：保留 `maxEvolveTimes=10`，拆两段：
  - 第 1~3 次 = 形态阶段（Lv10/35/60 换形态 + 技能升 I/II/III 档），成长 +0.1~0.2 象征性

- **关键机制：技能档位由「形态在树中深度」决定，不由 evolveTimes**（涅槃清零 evolveTimes 但保留形态 → 技能不退档）。新增 `Config.pet.evolution.formInfoOf(name)` 沿 tree 下探返回 {final, depth}；`skillOf(name)` 签名不变（battle.js/vtest_awaken_mutant 零改动），按 depth 定档返回副本 + tier/tierName 新字段，id/name 不动。

## 服务器权威挂机（battle-settle）重新接入 —— 解决「最小化就不打」
- **根因**：浏览器对隐藏标签页强制节流（setTimeout ≥1 分钟、rAF 冻结、Chrome 隐藏超 5 分钟整体冻结）。战斗循环跑在客户端 →「最小化还在打」不可能成立。今早的本地 delta-time 补步是路线错误，不是写法问题。
- **关键前提（省了一大半工）**：云端 `battle-settle` EF 一直在跑（无 token 请求返回 401）；`idle_sessions` 表 + `battle_session`/`battle_settle` 两个 RPC 全在库（用 anon key 探 rpc 返回 NO_ACTIVE_SESSION / SESSION_NOT_FOUND 可验证）。**服务器那半不用重写**。资产从 `_backup_rollbackB_20260904/_backup_rollbackA_20260904/supabase/` 恢复到 `supabase/`（含 functions/）。
- **不用重新部署**：`config.js` 最后改动是 09-04 08:52，之后没动过 → 云端 config-server.mjs 已是最新。判断依据：`git log -1 --format=%ai -- docs/js/core/config.js`。
- **新文件** `docs/js/core/idle-bridge.js`（替代已删死代码 `server-idle.js`）。刻意做笨，**不做**：剧本回放(playScript)、8 秒高频、失败退避分级、换宠自动重开、搬掉落。只做：30 秒 settle + 覆盖式应用 + `getLastCatchUp()`。
- **核心机制**：本地战斗循环照跑（演出+掉落+即时经验，手感零变化），服务器每 30 秒下发真值**覆盖** pet.level/exp/curHp。最小化时本地冻住但服务器照算，切回来一次补上。
- **两个坑（已处理）**：① 双写冲突——`serverManaged()` 时 main.js 跳过 `syncPetProgress`，停止时也不 flush（否则盖掉服务器值）；② 满级 exp 不覆盖——服务器 grantExp 用「凝晶石」计数且会重复累加，本地走 expPool，两套不一样，`r.level < maxLevel` 才覆盖 exp。

- **退路**：URL 加 `?noidle=1` 整体关闭服务器托管，退回纯本地挂机。
