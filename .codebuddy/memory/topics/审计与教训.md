# 审计沉淀 / 可复用教训

> 入口：`MEMORY.md`｜**审计、动资产、写不可逆逻辑、写迁移之前先读本文件。**
> 本文件按需读取，不占每轮注入预算 —— 有新教训直接往下加。

## ⭐ 两个系统性病因（本项目头号病因）
1. **「注释说 A、代码做 B」** → 拿注释 / 文档当**意图源**反查代码，是性价比最高的审计手法。
2. **「同一逻辑复制两三遍、只有一份对」** → 发现第二份就合并，别想着"保持同步"。

## ⭐ 发布：本地好好的 ≠ 线上没问题
- **引用只在 HTML 里查是不够的**：`app.css` 的 `url()` 同样是「页面引用的资源」
  （2026-09-17 抓到第二例：登录背景图在磁盘、从没入库 → 线上 404；第一例是 `ui-onboarding.css`）。
  ⚠️ CSS 里相对路径的基准是 **CSS 文件自己所在目录**（`../assets/x.jpg` 相对 `docs/css/`），不是 `docs/`。
  现在由 `docs/tests/vtest_assets_tracked.js` 一起守（游戏.html + 14 个 css，353 个引用）。
- **`.gitignore` 里指向某个文件的规则，一旦该文件入库或被搬走，规则必须跟着删** ——
  留着的旧条目只会静默坑人（同一剧本会重演；09-17 顺手删掉了 `docs/AI假人经济系统策划_v1.md` 那条）。

## RLS / 权限
- ⭐ **RLS 只控行归属、不控列 / 值**。已收 `materials` / `profiles`，**未收** `pets` / `equip_items` / `pet_egg`
  —— 施工图见宪法 §三 #8 与 `docs/待办/资产表收口调研_2026-09-13.md`，**别重摸**（现在 revoke 会挂掉打造 / 进化 / 涅槃 / 穿戴 / 掉蛋）。
- ⭐ **PostgREST 只认【表级】权限** → 保护某列**绝不能**靠"收表级写权限"，必须用独立表 / 触发器 / RLS with-check。
- ⭐ 判定事实搬服务端后，**本地那份副本就成了"显示状态"**，必须有回灌通道，否则玩家「看得见点不动」。

## ⭐ 资产安全：顺序就是一切
- **不可逆操作排最后**（nirvana 血泪）：快照（traits **深拷贝**）→ 更新主宠（可逆）→ 成功才删副宠。
- **先付费后给货**：扣费排在「确认能发货」**之后**；容易退的先扣；扣不动 → 整单放弃 + 退回已扣，
  **绝不「只 log 继续」**；记账成功但发货失败 → 必须有**玩家可见提示**。
- 🔴 **确认云端建档成功之前，不许删素材宠 / 扣素材**；删素材宠必须**先删云端成功，再删本地**。
- ⭐ `Materials.gain` 只入队（4 秒后上报）→ 发奖 / 退款后要自己 `flushMaterials()`。

## 测试四戒
输入按被测函数**真实收到的结构**造；新护栏**必做变异测试**验证它会红；极端状态同节复原；用**绝对值**断言。

## 迁移脚本
- 🔴 **迁移脚本不许重放**：同一函数被多个 `migrate_*.sql` 重复 `create or replace` 过，**谁后跑谁生效**
  —— 所以"迁移幂等、可重复跑"这句话是**假的**（已从事实源表格里划掉）。
- **安全守卫类函数的唯一定义在 `supabase/migrate_security_reapply.sql`**（幂等）。改函数请**新建文件**，
  别回头改已执行过的文件；确实要重放旧文件，跑完必须再跑一次 `migrate_security_reapply.sql`。

## ⭐ 展示层必须派生，不许手写第二份（2026-09-17）
起因：用户问完塔掉落，反问「所以百科里面的东西一个都没有修改？」——**"改了底层、百科没跟"是玩家一眼能看出的错**。
现状：材料词条（`mat-wiki.js` / `ui-mat-entry.js`）是派生的 ✅；百科页 `ui-codex.js` 的规则文案是手写的，
8 处停在 09-11 前（详见 `2026-09-17.md` 追加15）。
🔴 最离谱的一处：**它读了一张已作废的表**（`equipment.materialTierWeights`，09-11 起无人读取）
算出"图 10 掉 T1 底材 42%"，而**同一页下面**写着"图 10 底材最高 T3" —— 自相矛盾挂了两周没人发现。
🔴 更隐蔽的坑：**读一个不存在的字段不会报错**，只会静默取兜底值。
`Config.areaLevels` 从来没定义过（真表是 `Config.equipment.areaLevels`）→ 百科把"图 10 的装备等级"显示成 **1**。
⇒ 百科里出现"1""0%"这类怪数字，当 bug 查，别当设计。
✅ 规矩：**展示给玩家的规则/概率文案，能从 config 派生的必须派生**（`ui-codex.js` 头部早写了这条，是执行没跟上）；
确实必须手写的（如腐印来源概括），改 config 时回头对一遍。
✅ **治本三件套（2026-09-17 落地，以后新功能照这个来）**：
1. **「算数值」的实现只留一份**：`equipment.js` 抽出 `tierPool()`，`rollAffixTier()`（真抽取）与
   `tierOdds()/bestTierAt()`（展示层问概率）**共用它**。展示层一律调模块的公开口径，**不许自己复刻一份算法** ——
   复刻出的数字看着很正常，所以漂了也没人发现（这就是这次挂两周的根因）。
   ⚠️ `tierPool` 已进 `gen_equip_gen.js` 的 FUNCS 清单（服务端副本靠抽取）→ 改 `equipment.js` 后必须
   `node supabase/gen_equip_gen.js`，并由 `vtest_equip_gen.js` 验证前后端逐字段相等。
2. **加体检测试 `docs/tests/vtest_config_refs.js`**（新增护栏，**已做变异测试**：注入 `Config.towerDropz`
   与 `.materialTierWeights` 各一条，两条都红且报出文件行号）：
   ① 生产代码（`docs/js/**`）引用的 `Config.<顶层键>` 必须存在（这次 `Config.areaLevels` 那种）；
   ② 不得引用**已作废但仍在 config 里存档**的表（DEPRECATED 清单：`materialTierWeights` / `rarityWeightsByTier`）
   —— 「表还留在配置里」正是它被误读两次的原因；
   ③ 百科页必须走 `Equipment.tierOdds` / `bestTierAt`，不许自己读权重表复刻。
   ⚠️ 写这类扫描器**必须先把注释剥干净**（本项目注释里到处是「读 Config.xxx」「见 Config.yyy」），
   第一版用字符类正则剥、漏了行注释 → 立刻误报，咬了自己一口。
   ⚠️ `Config.nirvana || Config.merge` 这种**历史兼容回退**放 KNOWN_ABSENT 白名单（明知故犯，不是读错源）。
3. **能写定性就别写数字**：少写一个数字就少一个会漂的地方。"T1/T2 只有塔能出"这种定性结论，
   比"图 10 掉 T1 底材 42%"更耐用，变错时也更容易被发现。
⚠️ `vtest_codex.js` 只断言"名字出现过 + 无 NaN/undefined"，**抓不出文案与数值不符** ——
   真正的保障是上面三条；测试能兜住的是"读错源"那一半。

## 🔴 注释也会撒谎：删来源 / 改数值时必须回头搜"提到它的注释"（2026-09-17）

案例：`通天塔重置卡` 的「每周兑换『塔券铸成』」**2026-09-16 就删了**，
但 `tower-config.js` 的 `resetCard` 上方注释里还写着
「⇒ **玩家拿到它的唯一路 = 每周兑换「塔券铸成」**」—— 一条**不存在的来源**，
下一个会话照着它就会得出"这东西有来源"的错误结论。
`vtest_config_refs.js` 抓不到它（它只查 `Config.<顶层键>` 的**代码引用**，不查注释里的谎）。

⛔ **规矩**：删掉一个来源 / 改一个数值后，**全仓搜一遍这个名字**，把
「文件头注释 / 字段旁注释 / 文档表格 / 百科文案 / 任务说明 / SQL 注释」里**承诺过它的地方**一并改对。
（AGENTS §八 早有一条同源规矩：「移动/改名文档后必须全仓搜旧文件名再改引用」，本条是它在**语义层**的推广。）

## 🔴 名册类重复只能静态查重（2026-09-17）

案例：`Config.trade.materials` 里 `锁魂玉` / `琼浆玉露` **各登记两次**（同 id 同 name 连着两行）。
**行为**：不报错、不崩 —— 按 id 去重的消费方（`market_bot` 的 `find(m=>m.id===...)`）只取第一条，
所以只是"市集下拉多一个重复选项 + 交易记录页多渲染一对 chip"。**肉眼永远发现不了。**

⛔ **规矩**：凡「白名单 / 登记表 / 名册」（`trade.materials`、`materialInfo`、`towerDrops.items`、
道具表、掉落下拉……）都要有一条**按 id 与名字双重查重**的断言。
参考实现：`vtest_resource_matrix.js` 第 6b 节。
