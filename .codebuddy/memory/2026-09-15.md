### 调研：TapTap 迁移可行性（**用户已拍板「算了」→ 搁置，别再提**）
结论：**三条路只有 APK 套壳一条可行**，其余两条对本项目是死路。
1. ❌ **TapTap 小游戏**（`developer.taptap.cn/minigameapidoc`）：官方文档明确「**没有 BOM 和 DOM API**」，渲染须走引擎 Adapter（`tap.createCanvas`），官方只适配 Cocos Creator 3.8.x+ / Laya / Egret。
   → 本项目是 **DOM+CSS 驱动**（`游戏.html` 的 fs-panel/fs-btn + 大量 `innerHTML`），进去连 div 都建不出，**等于用 Cocos 重画整个表现层 = 重做不是迁移**，与「禁止重构」铁律冲突。判死。
2. ❌ **H5 直发**：需 **HTTPS + 已备案国内域名**（ICP 备案 + 主体），现挂 GitHub Pages 无备案，且官方无明确公开入口（仅第三方项目文档提及）。
3. ✅ **APK + TapPlay**（`developer.taptap.cn/docs/sdk/tap-play/input/`）：APK 套壳 WebView，DOM/CSS 完整可用，代码几乎不用动。TapPlay 红利=免安装、**免接防沉迷 SDK/实名**、存档备份。
   代价：新增安卓外壳工程 + 登录必须换成 **TapTap 登录/手机号/游客（明确禁止微信QQ）** + 触屏适配。
