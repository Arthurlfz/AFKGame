## 吸血/暴击/暴伤词缀与掉落词缀接入（2026-08-29 下午，用户问"吸血这些属性没有接入吗"）
- **根因 1（核心 bug）**：`getEquipBonuses` 里 crit/critDamage/lifesteal 词缀公式 = `装备基底值 × 词缀%`，而装备基底几乎不带吸血（仅护符基底 4），导致吸血词缀 +6% 实际贡献 0.24，等于废词缀。**修复**：机制百分比词缀直接加「百分比点数」（own[type] += aff.value），getStats 再 /100 转小数。
- **根因 2（掉落装备永远白装）**：`drop.js pickDropRarity` 返回**字符串**（'white'），`generateEquipment` 读 `rarity.affixMin` = undefined → randInt 得 NaN → 词缀补全循环跳过，掉落装备永远只有 1 条基础词缀。**修复**：改为返回稀有度对象。
- **根因 3（掉落类词缀死代码）**：dropQty/dropRare/matDrop 三个词缀在 getEquipBonuses 算了 resources 但掉落逻辑完全没用。**修复**：drop.js rollReward 读取出战宠物装备的 resources——
  - matDrop：提升所有材料类掉落概率（涅磐兽/合成之石/石头/进化素材/专属材料 × 掉率）
  - dropQty：材料掉落有概率多掉 1 个
  - dropRare：装备掉落有概率升一档稀有度（白→蓝→金）
- 验证：临时脚本全过（白1/蓝2/金3+ 词缀；吸血词缀 +6% → 面板吸血 6.0%）；`vtest_affix.js` 21 项全过；lint 无报错。
- 玩家感知链路确认：宠物面板显示吸血% → 战斗 calcDamage 命中→暴击→吸血回血。
- **吸血回血飘字已接（用户要求"要加入"）**：UI 飘字系统其实早有 `lifesteal` 类型（FLOAT_LABEL.lifesteal='吸血'、侧边暗绿 #6b8847、fs-float-up-right 动画），只是 battle.js 从没调用。已补：doTurn 里 `heal>0` 时 `window.UI.showDamage(isPet?'pet':'enemy', heal, 'lifesteal')`，攻击者头顶弹绿色「吸血：+X」。battle.js 版本号 bump 至 20260829z。
- **装备公式模型已确认生效（用户追问"词缀是不是只作用于装备属性"）**：当前实现即用户要的模型——`最终属性 = 宠物裸属性×(1+百分比词缀总和) + 装备底材固定值 + 其他固定词缀`。

## 战斗经验"看不见"三处根因修复（2026-08-29 晚，用户报"打完怪没经验、console 不显示"）

## 经验与消息系统重构（2026-08-29 晚，用户批"要第一性原则，不是打补丁"后重做）
> 上一版只是"把经验条刷新提到早退之前 + 给经验加一条 console 播报"，属于在坏结构上打补丁，已全部推翻重做。
### 1. 消息系统：53 处 addLog 全在写死节点（真根因）
- `UI.addLog` 原本写 `#battle-log`，而该 div 在 `游戏.html` 里是 `display:none`（v2 布局早已不展示战斗过程）→ **全项目 53 处播报（升级/进化/合成/打造/分解/登录/读档失败/战斗每回合）全部掉进黑洞**，且隐藏 DOM 每回合 append 从不清理，挂机一小时 = 几千个废节点（内存泄漏）。
- 修法：`addLog(text)` = 纯文本日志（内部 escapeHtml，防 XSS）、`showToast(title, html)` = 富文本提示（调用方负责安全，用于进化结果/分解清单这类带 `<b>/<br>` 的）。**两者都进同一个底部控制台（system 分类）**。已删除 `#battle-log` 元素 + `.battle-log/.log-entry` 全部 CSS。

### 2. 战斗过程不进消息流
- battle.js 删掉每回合的攻击/闪避/遭遇日志：立绘飘字才是战斗过程的表达层，写进控制台只会把掉落和经验冲掉。控制台只收**结果事件**：开始/停止/回血/战败/经验/掉落。胜利不单独播（经验条目已代表打赢）。
### 3. 经验：单一事实源（结构上杜绝显示与实发对不上）
- 规则全收进 `pet.js`：`expBase(enemy,area)` → `expFromBattle()`（实发，main 用）/ `expRange()`（预览区间，怪物 tooltip 用）。UI 与结算同源，不可能再出现"tooltip 说 +80、实际给 27"。
- 参数只在 `config.exp`。**公式变了只需改一处**。
### 4. 经验曲线第一性设计：产出与需求必须同量纲（这才是"感觉没经验"的根因）
