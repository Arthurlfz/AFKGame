## 挂机系统三处根因修复（16:00~16:20，用户报「过几分钟自动停 / 挂一夜没满级 / 进化后等级退回」）

先说取证结论（都是**代码里核实过**的，不是凭记忆）：
- 战核的 30 秒剧本窗实测只跑 **3 场**（每场 7~14 秒，`debug_script_chain.js` 实测）；
  `simulateSessionScript` 有 **`events.length < 200` 的硬上限**，200 场 ≈ **43 分钟**游戏时间（vtest 实测 2615800ms）。

### 问题一「点开始挂机后过几分钟就自己停了」→ 根因：静默停机 + 零日志
- `handleSettleError` 收到 `NO_ACTIVE_SESSION`（会话被别处 stop / 服务端状态不一致）时**直接 `stopLocal()`**：
  拆演出、放占用权、按钮变回「开始自动战斗」——**一条日志都没有**，控制台干干净净。这就是"自己停了"。
- 改法（第一原则：**只有玩家主动操作才该让挂机停**）：`recoverSession()` 自愈 —— 用当前地图 + 出战宠
  重新 `start` 会话继续挂（10 分钟内最多 3 次 → 超限才明确停机 + 说明原因）；`PET_NOT_FOUND` 明确停机；
  `stopLocal(reason)` 一律带原因（测试 Q2 守：全文件不许再出现无参 `stopLocal()`）。
- 顺手修掉一个真缺陷：同一段录像重发（`sameScript`）时原来把 `nextScriptTryAt` 清零 →
  **本地剧本已播完时每帧打一次 EF**（60+ 次/秒）。现在重发时退避 2 秒。

### 问题二「挂了一整夜，宠物仍未满级」→ 根因：时间被"客户端心跳"绑死，心跳停了时间就作废
- `battle-settle/index.ts` 的 `GRACE_SETTLE_SECONDS = 120`：**客户端 120 秒没来结算，这段时间直接作废**。
  而浏览器会冻结后台标签页（Edge 睡眠标签页 / Chrome 内存节省）、电脑还会休眠 → 心跳停几十分钟到几小时 → 一夜白挂。
  这和 EF 自己头注释写的设计意图（「切后台/最小化都不影响，服务器惰性结算兜住」）**正好相反** = 典型的"注释说 A、代码做 B"。
- 改法：`MAX_CATCHUP_SECONDS = 8 * 3600`（上限内按真实经过秒数全补，超过的部分作废，防"关几天回来补三天收益"）
  + **结算游标只按「真正算掉的时间」推进**（`fromMs + coveredMs`，不再是 `now`）——
  补账窗撞上 200 场上限时，没算完的秒数留在账上，下次继续补，时间不再凭空消失。
  为此 `simulateSessionScript` 新增返回 `consumedMs`（**两份战核副本已同步**，vtest_sim_sync 守）。
  实测：8 小时积压 → 每次 settle 补 43 分钟 → 约 11 次 settle（≈5 分钟）追平。
- ⚠️ **EF 没有重新部署，线上还是老逻辑**（本机没有 SUPABASE_ACCESS_TOKEN，Supabase 集成也没有部署能力）。
  命令：`$env:SUPABASE_ACCESS_TOKEN='...'; npx supabase functions deploy battle-settle --project-ref asklogeayzlqpeejuvjj`
  （ref 以 `docs/js/core/supabase.js:15` 为准）。**不部署 = 问题二等于没修。**

### 问题三「本地显示 60 级能进化，进化成功后等级突然变回去」→ 根因：本地等级是"演出预演值"
- 托管挂机期间秒级回放里，`pet.level/exp` 是**预演值**：`installScript` 把它设成"窗前真值"，再随每场击杀往上加；
  而服务器**在结算那一刻就把整段窗口的账写进库了**（云端领先本地最多一个窗口）。
- 于是任何"读本地等级做不可逆操作 + 写云端"的路径都会出事：进化/合成/涅槃拿预演等级判门槛（`pet_evolve.js:135`、
  `pet_merge.js:166/348`），涅槃还会把等级写回云端（回滚分支写 `snapshot.level`）→ 之后真账校准又把本地写回服务器那份
  → 玩家看到的就是"进化成功、等级却跳回去"。进化本身有 1~2 秒 await，正好让结算落在中间，所以症状**表现得像进化引起的**。
- 改法：`IdleBridge.duringPetEdit(fn)` —— 挂机中先 `shutdown()`（结清真账 → 本地被真账校准）→ 执行 → **自动重新挂上**
  （同图同宠）。已接线：`Evolve.evolve` / `Merge.nirvana` / `Merge.synthesize`（`withIdleHold` 包装，IdleBridge 不在时零影响）。
  另加两道闸：`main.js flushPetProgress` 托管期间不写（原来是"本地不许写"只挡住了 visibilitychange 一处）、
  开发面板 `savePet` 托管期间拒绝并提示。

## 换图挂机"过几分钟失效、要重新进图再点"（16:30~16:35）

用户新报：一张图挂着，换到另一张图点「开始挂机」，过几分钟挂机失效，得重新进图再点。

**根因（代码里可证实的结构性缺陷，3 条叠加）**
1. 🔴 **世界地图的启动方式本身就是"靠运气"**：`ui-worldmap.js#nd-idle` 不是直接启动，而是 `setTimeout(150)` 之后**替玩家点一下主按钮**。能不能挂起来取决于那一刻按钮的状态机（`BattleSession.holder()` 是否为空 / `getCurHp>0`）。
   任一不满足 → **静默失败**（或走成"停止"分支）→ 玩家看到的就是"点了挂机、过一会儿发现根本没挂上"。**这就是"为什么会出现"的直接答案。**
2. 🔴 **占用权可以被"过期的动作"撤销**：`BattleSession.release(kind)` 只比 kind、**不比"这是不是我这轮占的"**。
   而 `ui-worldmap.stopRunningIdle()` 是 `await IB.handoff()`（等一次网络结算！）**之后**才调 `B.stopAutoBattle()`，
   它无条件 `SESSION.release('wild')` → 这段时间里新挂机可能已经 claim 上来了 → **迟到的交还把新挂机踢出战斗页**。
   （同一类雷：`main.js` 的 `stopGameRuntime` 也是不 await 就调 `stopAutoBattle()`。）
3. 🔴 **切换期间按钮零反馈** → 玩家必然再点一次 → 两次点击在不同时刻停/起会话，正好踩 1 和 2。

**修法（根治，不是补丁）**
- `main.js` 新增统一入口 **`startIdleAt(areaId)`**（主按钮与世界地图共用同一个函数）：选图 → 0 血门槛 → 托管/本地分流 → 失败原因如实回报。导出给世界地图用。
- `ui-worldmap.js`：**直接调 `Game.startIdleAt`**（删掉 `setTimeout(150) 点主按钮`）、失败弹 toast、切换期间按钮禁用 + 文案"切换中…"（`dataset.busy` 防连点）。
- `battle.js` / `idle-bridge.js` 各加 `pageClaimed` 标记：**只交还自己确实持有的那一份占用权**，过期释放再也伤不到新占用者。

**测试**：`vtest_prep_page.js` 改 A7（断言走统一入口）+ 新增 A10（断言不再点主按钮）+ A2-1/A2-2（连点两次只启动一次、结束后解锁）；全量 `npm run check` **71 通过 / 5 失败，无新红**。
`游戏.html` 升 `?v=`：battle=20260913pagesafe1 / idle-bridge=20260913idle5 / main=20260913idlefix2 / ui-worldmap=20260913switch1。

**未完成 / 待确认**：无法在真浏览器里复现用户那次具体触发（本地只能改代码，不能操作他的浏览器）。
上面第 1、2 条是**代码里看得见的缺陷**，但它们是否就是那次"几分钟后失效"的唯一原因，**需要用户强刷后复测确认**；
若仍复现，日志现在会点名"是谁停的、为什么"（自愈/停机一律带原因），拿到那段就能一击定位。
⭐ **可复用教训**：`BattleSession.release(kind)` 无身份校验 —— 任何"await 之后的无条件 release"都是雷；
下次动这块应考虑做成 token 制（claim 发凭据、release 验凭据）。
