
## 装备产出密度与 T1 稀缺性调研（策划视角，2026-08-30，用户问"T1 太容易 + 装备又多又乱"）

### 量化现状（实测 1 场 ≈ 10 秒 → 360 场/小时）
| 产出 | 概率 | 每小时 |
|---|---|---|
| 装备 | 5%/场 | 18 件 |
| 重铸石 | 5%/场 | 18 个 |
| 剥离+神圣+增缀石 | 14% 合计 | 50 个 |
| 宠物蛋 | 5%/场 | 18 颗 |
- config 注释里的设计意图是「20 场掉 1 件」，那按每场 30 秒算 = 2 件/小时。**战斗节奏后来快了 3 倍（speedScale 调回 12），掉率没跟着调 → 实际产出是设计意图的 9 倍**。

### T1 三处来源（从最容易到最难）
1. **重铸（真凶）**：`equipment_craft.js reforge` 里 `randInt(1,5)` 均匀随机，**完全不看稀有度** → T1 概率 20%，白装也能洗出全 T1；重铸石 18 个/小时 → 可无限刷。**稀有度系统被重铸整个绕过**（白装重铸后可有 6 条词缀，比金装还强）。
2. 金装掉落词缀：`affixTierByRarity.gold = [1,3]` 均匀分布 → 每条 33% 是 T1；金装平均 4.5 条 → **每件金装平均 1.5 条 T1**。
3. 增缀石新增词缀：T 阶 1~5 均匀 → 20% T1。
- 底材 T：`rollMaterialTier` 图1 → T1 概率 6.7%；图6 → 33%（T1 倍率 1.5 是最好底材）。

### 「又多又乱」的根因
- 价值维度太多且不可比：部位 × 图档 × 底材T × 稀有度 × 词缀类型 × T阶 × 数值 → 玩家每件都要"研究一下"，18 件/小时堆起来就是乱。
- 缺单一标尺（没有装备评分），缺批量处理（只能一件件看/分解），背包无上限，市场摊位只有 5 个（装备出不去）。

## 任务可重复提交漏洞修复（用户："刷新后能重复完成，连点会重复拿材料，不许打补丁"）

**四个叠加根因**（前三个是并发/时序，第四个最隐蔽）：
1. **重入**：`completed[id]=true` 写在所有 await 之后。发奖走 `Materials.gain` → 云端 RPC `add_material`（**累加型**），
   连点在 await 空隙重入 = 重复加材料。实测连点 5 次发 5 份。
2. **持久化不等候**：`saveProgress()` 不 await + `.catch(()=>{})` 静默 → 刷新即丢。
3. **并发覆盖**：`quest_progress` 是**整行 JSON 覆盖写**（upsert）；挂机每场胜利都 `reportType → saveProgress`，
   与交任务的写入并发时，后到的旧快照抹掉先写的新状态。
4. **空历史覆盖（主因）**：页面刚加载、玩家还没登录时，`getQuests() → ensureDailyReset()` 就会触发一次
   `saveProgress()`，此时内存是空的 → 拿空历史整行覆盖云端，把以前交过的任务全抹成未完成。
   **写入一直是对的，是被这次空写抹掉的**——光盯 completeQuest 查不出来。

**修复（quest.js + main.js + ui-quest.js）**：
- ① `submitting` 同步闸门：任何 await 之前入集合，finally 释放
- ② 状态先行：标记「已交」放在发奖之前。扣材料失败可回滚（一份未发，安全）；发奖失败**绝不回滚**（回滚 = 还能再领一份）
- ③ `saveProgress` 串行队列：所有写排一条队，快照一律从内存取（内存是唯一同步真相，绝不读云端再改写）
- ④ 交任务 `await saveProgress()`：不等落盘就返回，玩家一刷新读到旧进度
- ⑤ `cloudLoaded` 闸门：进度没拉回来之前**禁止写也禁止交**（修根因 4）
- ⑥ `loadCloudProgress` 提到 `restoreCloudPets` 里登录后必经处并 await —— 原来只在「有宠物」分支调、且不 await，
   新号走 `showStarterPicker` 分支永远交不了任务；读失败不能阻断登录（加 catch，只 warn）
- ⑦ UI 提交按钮提交期间 disabled（闸门是最后防线，这里只是不弹无谓报错）

**测试**（`vtest_quest.js` **53 项全过**，新增 6 项幂等断言）：
- 连点 5 次只有 1 次成功、材料只 +2（m1 给进化素材×2）
- 并发上报下先交的任务不被覆盖；刷新（reset + 重拉）后不能重复交、不多发材料
- **验证过测试有效性**：临时回退成旧逻辑 → 报「连点 5 次只有 1 次提交成功（实际 5 次）」FAIL，确认断言抓得住

**踩坑**：
- 测试桩 `vstub.js` 原本没有 `quest_progress` 表 → `client.from(...).upsert is not a function`。已补（`globalThis.questTable`）。

  与 `reload`（只清内存+重拉=刷新）两个 helper，注意两者语义不同、别用错。

## 🔴 逐帧动画"网页里不显示"根因修复（2026-08-30 晚，用户："刚做了动画模型但网页还是不显示"）

**根因 1（致命，图 404）**：`--as` 自定义属性里塞的是相对路径 `url('assets/...')`。
**CSS 自定义属性中的相对 url() 由浏览器按【样式表所在目录】解析**（game.css 在 `css/`，于是解析成 `/css/assets/pets/anim/...` → 404 → 整块背景空白）。
实测 `getComputedStyle().backgroundImage` = `http://127.0.0.1:8030/**css**/assets/pets/anim/...` 一击命中。
JS 层全对、素材全对（1536×256 单行、6 帧都有内容）、版本号也 bump 了——光看代码永远查不出来，必须读计算样式。
**修法（第一性）**：URL 不再进自定义属性，`paintAnim()` 直接写 `node.style.backgroundImage`（内联样式按文档解析，与 `img.src` 一致）；CSS 删掉 `background-image:var(--as)`。
**根因 2（丢帧）**：`steps(帧数-1)` + 位移 `(帧数-1)×100%` → steps(N) 默认 end 模式只呈现前 N 个采样点，**第 6 帧永远播不到**。
**修法**：`--steps = frames`、位移 `calc(var(--af) * -100%)`。实测帧序列唯一值 = 0/-100/-200/-300/-400/-500 六帧全播。
**根因 3（攻击不重播）**：换 background-image 或 iteration-count 都不会重置已在运行的 CSS 动画计时。
**修法**：`restartAnim()` = `animation:none → 读 offsetWidth → animation:''`（Web 平台标准重启手法）；`setAnim` 加同动作幂等判断。
**验证（真实浏览器，1080p）**：`UI.resetBattle('影刃兔…')` 真实路径下我方/敌方都挂上 `.pet-anim`，URL 正确，rect 280×280 无遮挡，600% 100%，steps(6)。

## 🔴 网络延迟优化第一轮：`getCurrentUser` 不再每次打服务器（用户："点一下就有延迟"）

**优化前每个动作的等待**：
| 动作 | 链路 | 耗时 |

### 宠物平衡：拉平的是【净推进】，不是裸 DPS（核心教训）

## 怪物等级改为「钳进地图等级段」（2026-08-30 深夜，用户："怪物的等级要匹配地图的等级，而不是宠物等级"）

**最终公式**：`怪等级 = clamp(宠物等级, 图下限, 图上限)`（`battle.js rollEnemyLevel`）。
即**图决定范围，宠物等级决定范围内的取值，走到边界就停**。
| 场景 | 怪等级 |
|---|---|
| Lv3 在图1（1-6） | Lv3（=宠物等级） |
| Lv60 在图1 | **Lv6**（图上限，不再跟涨） |
| Lv1 在图10（55-60） | **Lv55**（图下限，越级即硬门槛） |

**老毛病**：怪等级 = 宠物等级且不设边界 → Lv60 打图1 也出 Lv60 怪，图的等级段形同虚设，
图与图没区别、赖在低级图也能拿满经验（经验 = coef × 怪等级）。钳住后图1 封顶 6 级 → 想拿高级经验必须去高级图。

### ⭐ 中间翻车：先做成「图段内纯随机」，被数据推翻
用户第一版拍板"图段内均匀随机、完全不看宠物等级"，实现后量化发现**新手会卡死**：
- 根因：强度按 `怪等级/图中点` 缩放（scaleEnemyStats），而**低级图的等级段相对中点跨度极大**：
  图1 [1,6] 中点 3.5 → 段内跨度 **5.6 倍**（1级=0.29倍 ↔ 6级=1.6倍）；图10 [55,60] 中点 57.5 → 跨度仅 1.04 倍。
  → **越低级的图，段内强度浮动越失控**（这是"每图固定 6 级"+"按中点缩放"的必然结果）。
- 实测（玩家 Lv1 在图1）：遇 Lv1/Lv2 怪能赢（掉血 1%/46%），**遇 Lv3 怪 5/8 只打不过，遇 Lv4~6 全灭**（掉血 307%~1239%）
