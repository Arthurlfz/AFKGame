## 战斗「伤害没出来怪就死」+「与服务器对不上」诊断（2026-09-09）
- **两份战核副本（关键事实）**：①`docs/js/core/battle-sim.mjs`（656 行，含 `simulateSessionScript` 带时间轴版，前端预演用；`build-sim-global.js` 生成 `battle-sim.global.js`）；②`supabase/functions/_shared/battle-sim.mjs`（596 行，服务器真账用）。**两份手工同步**，diff 显示差异：服务器版有 `godDefOf` 神级宠分支（`getBaseSpeed`/`getStatCoeff` 走神级宠），前端副本没有。⚠️但 `config-server.mjs` 里压根没有 `godPets`（0 匹配）→ 服务器 `godDefOf` 恒返回 null，两边都退化成普通宠；而**前端 `pet.js` 有 godPets 支持**（客户端 config 有）→ 神级宠面板属性 ≠ 战斗模拟属性（显示强、实战弱）。
- **症状 A「伤害没出来怪就死」根因（已修）**：托管演出有两条独立时钟 —— 血量走剧本时间轴（`showEnemy.hp = maxHp*(1-prog)`，随时间线性掉），飘字走 `setTimeout(hitAt)`（hitAt 随屏宽自适应，可 400ms+）。`gaugeTick` 里 `t >= f.t1` 一到就 `showEnemy=null` + 清场，**不等在飞的那一刀** → 最后一刀飘不出来，或迟到打在下一只怪身上（回调只挡了 `!active || waitingHeal`，没挡"怪已换"）。
  - 修法（`idle-bridge.js`）：新增 `pendingHits[]` 登记在飞的出手；`t >= f.t1` 时先 `flushPendingHits()`（clearTimeout + 同帧同步执行）再清场——**不推长剧本时间轴**（推长→播放时长>预演时长→服务器按真实时间多算几场→补发刷屏）；`run()` 开头加 `if (!showEnemy) return`；`stopShow`/`enterHealWait` 用 `dropPendingHits()` 清理。`vtest_idle_bridge.js` 全绿。

## 演出层改造：从「时间驱动血」改为「刀驱动血」（2026-09-09 已落地）
- 用户补充症状：①攻击进度条没跑完怪就突然死了；②飘字数字与血条扣减不一致。两者同一根因——托管演出里**血量走剧本时间轴线性插值**（`showEnemy.hp = maxHp*(1-prog)`），**飘字走 `rollShowDamage()` 真实公式**只当好看的数字，两者没有因果关系。
- 改法（3 个文件）：
  1. `docs/js/core/battle-sim.mjs` 的 `simulateSessionScript`：每场 event 新增 `petHits` / `enemyHits`（统计 `fight.events` 里 `by==='pet'|'enemy'` 且**不带 note** 的条数——血统追击/反伤/反击带 note，不是出手）。改完必须跑 `node docs/js/core/build-sim-global.js` 重新生成 `battle-sim.global.js`（浏览器加载它）。
  2. `docs/js/core/idle-bridge.js`：新增模块级 `showPlan`（petHits/enemyHits/petLeft/enemyLeft/petLoss），在 `mountShowEnemy` 里按剧本初始化；
     - 行动条定速 = `dt * 100 * 剩余刀数 / 剩余时间`（自适应，每一刀铺满剧本时间轴）→ 条满才出刀，不再"条没满怪就死"；
     - 扣血 = 「剩余血 / 剩余刀」× 暴击1.6 / 普攻0.85，**最后一刀兜底 = 剩余（正好归零）**；
     - **飘字 = 血条实际扣减的数字**（同源），miss 飘 0；
     - `showTurn` 开头加刀数闸门（打完 N 刀不再出手，避免血提前扣穿后怪站着等 t1）；
     - `showPlan` 为 null（老剧本/测试桩）→ 自动退回旧行为（速度公式 + 时间插值），测试桩不受影响。
- 兼容处理：`checkEnemySprite` 重挂立绘时改为传 `script.events[scriptIdx]`（否则丢 petHits），并用 `keepHp` 保住 showHp 不被退回本场起点；`mountShowEnemy` 开头 `dropPendingHits()`。
- 测试：`vtest_script_sim.js` 新增 E1 断言（每场必带刀数，实测输出 6/3、4/2、4/3）；`vtest_idle_bridge.js` 23 项、`vtest_server_sim.js`（前端 vs 服务器同种子 11场/255经验/宠血649）全绿。
- ⚠️ 未提交（等用户在浏览器验证观感后再提）。
- **第二轮修正（用户反馈"最后怪还有血、攻击没落到身上就死了"）**：上一轮定速公式 `100×剩余刀/剩余时间` **是错的** —— 它假设全程都能涨行动条，但出手期间行动条被冻结（己方 hitAt+backMs，对方出手再冻 hitAt）。实际可涨条时间远小于本场时长 → 速度被严重低估 → 刀根本出不完 → t1 一到 `f.win → showEnemy.hp=0` 强杀，于是"剩一截血、刀在半空、怪没了"。
  - 修正：新增模块级 `lastHitAt / lastBackMs`（showTurn 里记录真实演出时长），定速按**扣掉冻结开销**后的可涨条时间算：`avail = max(120, remainMs - (己方剩余刀×(hitAt+backMs) + 对方剩余刀×hitAt))`，`speed = 100×剩余刀/avail`。
  - 数值验证（node 手算，dt=16.7）：span/petHits/enemyHits = 3000/4/2→4刀、5000/6/3→6刀、2000/4/2→4刀、800/1/0→1刀；只有 1200/4/1 这种极端短场出 3/4 刀。
  - **收尾兜底**：极端情况下（刀没打完时间见底），最后 `tailMs = clamp(span×0.2, 120, 300)` 内把剩余血从进入时的 `tailHp` 线性平滑抹到 0 —— 硬保证"绝不让怪有血凭空消失"。正常打完时 tailHp=0，无副作用。
- 教训：**改演出节奏类逻辑必须手算/数值验证时间预算**，不能只看公式形式对不对；这次两次翻车都是因为"看起来合理的公式"没算上冻结开销。
- **第三轮修正（用户第三次反馈："服务器告诉本地打完了，画面怪就直接死了，直接下一场"）**——前两轮都修错了地方，真正的两个机制问题：
  1. **怪死于「时间」而不是「最后一刀」**：`gaugeTick` 里 `t >= f.t1` 是唯一出口，一到就 `showEnemy.hp=0`+清场+`scriptIdx++`。我一直试图"让刀追上时间"，方向反了 —— 应该是**让时间等刀**。修：把收尾逻辑抽成 `finishShowFight(f, now)`（flushPendingHits→归零→settleKill→animateVictory→showEnemy=null→scriptIdx++→重置行动条→needHeal 判定），两个入口共用：**刀打完（正常，`showTurn` 扣血后 `plan.petLeft<=0 && f.win`）** / **t1 超时（兜底）**。怪现在死在最后一刀命中那一刻，不是时间到凭空消失。
  2. ⭐**更可能是用户实际观察到的**：`bootstrapScript` 拿到新剧本后**无条件整体替换**（`script=sc; scriptT0=now; scriptIdx=-1`）。兜底 settle（`SAFETY_SETTLE_MS=120s`）和 `visibilitychange` 切回前台的 settle 都会在**当前这段播到一半**时触发 → 画面上正在打的怪当场被抹掉、从新剧本第一场重来 = 「服务器一说打完了，怪没了，直接下一场」。修：新增 `pendingScript` + `installScript(sc)`；`playing = script && scriptIdx < length && showEnemy` 为真时只攒不装，等 `scriptIdx >= length` 时由 gaugeTick 装上继续演。`startShow`/`stopShow` 清 pendingScript。
  3. 附带：`showEnemyMountedAt` 保护 —— 刚上台的怪若立刻撞上 `t >= f.t1`（切后台回来时间轴被快进），把 `scriptT0 = now - f.t0` 重对齐让它完整演一遍，而不是刚露脸就被清掉。
- **`installScript` 会重置演出态**（dropPendingHits / showPlan=null / showEnemy=null / 行动条归零），只在确认没怪在演时调用。
- 三轮翻车的元教训：**先定位「这个现象的触发点是什么」，再动手**。前两轮我盯着"刀数/时间预算"推理，其实用户第一句「服务器上面告诉本地打完了」已经点名是 settle 换剧本，我没接住。
- **第四轮：仍无效 → 停止推理，改取证**。加了诊断埋点（console.log，全部包 try/catch，绝不影响战斗）：
  - `idle-bridge.js`：`[战斗·模式]`（确认是否托管）、`[战斗·上怪]`（怪名/血/刀数）、`[战斗·收尾] 原因=lasthit|timeout`（+场序/怪血/剩余刀/t vs t1）、`[战斗·换剧本] 打断?`（是否抹掉在打的怪）、`[战斗·结算] 服务器场数/已演出/窗口秒`。
  - `battle.js` `endFight`：`[本地战斗·收尾] ⚠️battle.js 本地战斗（非托管）` —— 用来区分玩家到底走哪条路径。

- **零漂移机制**：script 带 expBefore/levelBefore（=补账后真值，grantExp 链式两步算出）；客户端 installScript 把本地 exp/level 重置到窗前真值逐场重演，演完正好 = expLeft/level。同 id 幂等重发（刷新/切回前台）→ 判重忽略，且 applyResult 传 skipExpLevel 跳过经验覆盖（否则"先覆盖成窗后真值再逐场加"=重复入账——K3 测试抓出来的真 bug）。
