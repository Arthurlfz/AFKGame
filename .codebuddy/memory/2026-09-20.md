## 追加14：🔴🔴 名牌"没显示"的真根因 —— **同一功能有两条渲染路径，我改的是没被执行的那条**

`chatMsgHtml(m)` 对 `cat === 'social'` 的消息**用结构化字段重新拼**一版：

2. `chatMsgHtml` 的 social 分支：名字改走 `UI.nameTag(m.name, key)`（key = 自己走 `perksCache.name_tag`，别人走 `chatTags[m.uid]`）。

## 追加18：🔴 神级宠待机动画"大部分时间看不见"—— 根因是 CSS 逐帧位移公式写错了（不是素材/不是加载）

**症状**：战斗页我方神狐基本空白，偶尔闪一下；受击时更容易看到。其他宠物（静态图）正常。

### 真根因：background-position 的百分比不是相对图宽，而是相对【容器宽 − 图宽】
- `background-size: calc(var(--af) * 100%) 100%` ⇒ 图宽 = 帧数 N × 容器宽 W
- 所以 容器宽 − 图宽 = **−(N−1)W** ⇒ **整个 100% 量程只等于「N−1 帧」的距离**
- 老写法 `to { background-position: calc(var(--af) * -100%) 0 }`（= −2400%）把图往**右**推了
  N×(N−1) 帧 ⇒ 第 1 步之后整张图飞出容器 ⇒ 只剩每轮开头那一帧可见（24 帧/2.4s ⇒ 只闪 0.1s）
- 正确值：走完全部帧 = **100%**；因 `steps(N)` end 模式只取到量程的 (N−1)/N，
  总量要放大到 **100% × N/(N−1)**，每一步才正好落在一帧上。
- 判据（不用开浏览器也能定位）：**图能加载 + 动画在跑** ⇒ 只有第 1 帧可见 = 一定是位移算错，不是 404/层级/素材。
  （若动画根本没跑，会永远停在第 1 帧 = 反而一直可见。）

### 改法
- `game.css` `@keyframes pet-anim-play`：`to { background-position: var(--shift, 100%) 0 }`，
  注释里写清推导（含"不能写 N×100%"这条反例）。
- `pet-sprites.js` / `游戏.html` 内联副本 的 `paintAnim`：新增
  `--shift = (frames > 1 ? frames/(frames-1)*100 : 100) + '%'`（**N/(N−1) 交给 JS 算**，
  CSS 里除以自定义属性不便携）。
- `ui-battle.js` 的 `mountIcon`：逐帧分支也写 `--sprite`（用同形态静态立绘当轮廓）——
  原来只有静态分支写，逐帧分支没有 `<img>` ⇒ `--sprite` 为空 ⇒ 受击闪光层 `mask-image` 失效、
  **糊一个白方框**。

### 守值测试（`vtest_pet_anim.js`，之前已红，本轮修绿）
- ⚠️ **老断言把错的公式当成了正确规则在守**（`calc(var(--af)*-100%)`、禁止 `frames-1`）
  ⇒ 这类"过时断言"必须连注释一起改，否则以后谁修谁红。
- 改为：断言 `--shift = 100%×N/(N−1)`（24 帧 → 104.3478%）、CSS 走 `var(--shift)`、
  全仓不再出现 `var(--af)*-100%`、两套副本都注入 `--shift`、两条挂载分支都写 `--sprite`。
- 另外 mountAnimated 现在只给「血月神狐」开 ⇒ 测试里挂载/切动作分别用对形态
  （切 attack 必须用影刃兔，神狐只有 idle）。

## 追加19（09-21）：🔴🔴 用户「完全不播放」—— 上面那版修错了方向，真凶是**动画里的 CSS 变量**

**症状（用户第二轮）**：立绘**能看到但完全静止**。
⭐ **看图定性的关键一步**：把截图里的立绘和两张素材图对比 ——
`pack1-bloodfox/monster-04.png`（静态：**坐姿红狐 + 背后红月**）vs `anim/god/血月神狐-test.png`（动画第 1 帧：**白/银双足直立狐**）。
截图里是**后者** ⇒ **挂载成功、`.pet-anim` 存在，只是动画没跑（静在第 1 帧）**。
⇒ 这一步把"回退静态立绘 / 素材 404 / z-index"全部排除掉了，省一大圈。

**真凶**：我上一版把位移改成 `to { background-position: var(--shift,100%) 0 }` + JS 注入 `--shift`。
**CSS 变量参与动画时一旦解析不出来，症状是「静帧」而不是报错** —— 肉眼分不出是"动画坏了"还是
"素材只有一帧"，这是本项目最贵的一类失败（对照：上一轮的"百分比算错"至少还会闪，这次连闪都没有）。

### 🔴 定案实现（以后改逐帧就照这个，别再动结构）
**两层 DOM + transform 位移 + 动画串内联、零 CSS 变量**：
- `.pet-anim`（裁切层，`position:relative` + `overflow:hidden`，撑满父容器）
  `> .pet-anim-strip`（帧条，JS 写 `width = 帧数×100%`、`background-size:100% 100%`）
- `@keyframes pet-anim-play { from{translateX(0)} to{translateX(-100%)} }`
- JS 内联写 `strip.style.animation = 'pet-anim-play 2.4s steps(24) infinite'`（**不含 var**）
- 为什么这样对：**translateX 的百分比相对【元素自身宽】**，而帧条自身宽 = 帧数×容器宽
  ⇒ `steps(帧数)` 每一步 = 100%/帧数 × 帧数×容器宽 = **正好一帧宽**，天然对齐，**不需要任何修正系数**
  （对比 background-position 的百分比相对"容器宽−图宽"，必错，是上一轮的坑）。
- 把"两层的正确关系"写成三条红线注释在 `game.css` 的 `.pet-anim` 段：①不用 background-position 百分比
  ②动画里不许出现 CSS 变量 ③图片 URL 走内联 background-image（自定义属性里的相对 url() 会解析到 css/ 下）。
