## battle-settle 500 修复（同日）：idle_sessions 缺 last_boss_fight 列
- 症状：前端每 2s 一次 settle 全 500，本地 vtest_server_sim 全绿、postgres 日志无异常。
- 根因：`migrate_idle_sessions.sql` 用 `create table if not exists` 建表，**后加的列对已存在的表永远不生效**；`battle_settle` RPC 写 `last_boss_fight` 时报 42703 → SETTLE_RPC_FAILED 500。
- 修复：`alter table idle_sessions add column if not exists last_boss_fight integer`（已执行），迁移文件也补了幂等 alter + 注释。
- 铁律沉淀：**给迁移文件里的旧表加列，必须同时写 `alter ... add column if not exists`**，光改 create table 是骗自己。
- 排查教训（又一次验证）：① `supabase_execute_sql` 多语句只返回最后一个结果集——查存在性必须单语句（差点误判 3 个 RPC 不存在）；② `search_content` 对大文件有假阴性（说 config-server.mjs 没有 echo-cliffs，Select-String 证明有）。取证一律 SQL 单语句 + Select-String 交叉。
- 本地复现手法有效：拉真实 DB 行 → node 喂给同一套 settle-core/battle-sim 跑，能快速切割"代码问题 vs 数据问题"。
