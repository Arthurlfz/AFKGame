## 服务器托管挂机实测 bug：切回前台「一秒几十场」狂跳爆发
- **现象**：用户实测最小化挂机，切回来瞬间疯狂跳、一秒打上百场。
- **根因**：`battle.js tick()` 里 9-03 加的「真实时间补步」（steps 封顶 600）还在。后台被节流 1 分钟 → 恢复瞬间 steps=600 同步狂跑。9-04 接入服务器托管时我保留了它（以为只对本地模式有用），但托管模式下本地循环还在跑，照样爆发。
- **修法（一处）**：`tick()` 里判断 `window.IdleBridge.isActive()` → 托管时 `steps=1`（绝不补步，后台冻就冻，服务器在算）；仅 `?noidle=1` 纯本地模式保留补步。battle.js 版本 `20260904idle2`。
- **教训**：给「本地演出」找权威源时，本地循环里所有"追时间"的逻辑（补步/dt 补偿）都要逐个排查——服务器托管后它们从"修 bug 的补丁"变成"爆发 bug 的引信"。main.js 回血时钟 dtSec 封顶 60 秒属同类，血量会被服务器覆盖暂无害，留意。

- **测试**（vtest_idle_bridge 新增 K/L 段）：K1 剧本 seconds=真实 elapsed(45)、K2 服务器 2 场演出 0 场 → 补发 2 次掉落、L1 补发上限 20。测试桩需在**第一次 settle 前**装好 window.BattleSim（loadSim 缓存首次加载结果，后补无效）。
- **验证**：node --check 过；vtest_idle_bridge/ui/script_sim/server_sim/settle_core 全绿。
- ⚠️ **测试进程残留坑**：Start-Process 后台跑 vtest 会留下永不退出的 node 进程（rAF/setInterval 桩不退出）→ 占住输出文件删不掉。跑完用 `Get-Process node` 找 Program Files 路径的残留并 Stop-Process（.workbuddy 的系统 node 别杀）。

## 第三批：补发刷屏根因与根治（已推送 `b38fba7`，idle-bridge `20260905match3`）
- **用户实测暴露**：几乎每 1~3 次击杀就跟一条"⚡ 补发 N 场"，13:39 切后台回来一次补 9 场——补发不是偶发，是**每段结算窗口系统性差 1-3 场**。
- **根因（第二批引入的结构性 bug）**：击杀分支 `scriptT0 += RESPAWN_GAP_MS(2200)` 把时间轴整体后推 2.2s/场 → **播放总时长 = 预演时长 + 2.2×场数**。而 settle 是"剧本播完才触发" → 结算间隔被空场净增拉长 → 服务器按被拉长的真实时间算账 → 每段都比预演多几场 → 持续补发。`lastElapsedSec` 做下一段预测只会把膨胀一路传下去（发散），13:39 补 9 场=切后台回来 GRACE 120s 结算 vs 演出几乎没动。
- **修法（收敛）**：**播放严格贴剧本时间轴走，任何击杀后的空场/后推/暂停全部删除**。场间 gap 用模拟器自带的 600ms（nextFightDelay 已在剧本 t0 里）；击杀后 showEnemy=null、scriptIdx++，主循环 `if (!showEnemy) { if (t >= f.t0) mount else 空场隐藏怪 return; }` 按剧本时点交棒。这样"播完即 settle"，结算间隔 ≈ 预演时长，差额归零，补发只出现在切后台/剧本失败等真异常。
- **SCRIPT_RETRY_MS 5s → 30s**：剧本失败（通常=长时间回血模拟 0 场）时不再每 5 秒打一次服务器（那会造成"5 秒一次结算 → 每次都补发几场"的刷屏），按正常窗口 30s 一次、差额一次性补齐。
- **教训（血泪级）**：**"观感空场"绝不能变成"时间轴净增"**。服务器是惰性结算（只在前端 settle 时按真实经过时间算账），任何"演出比模拟慢"都会导致每段欠场 → 补发刷屏。演出与模拟要么严格同步（时间轴同源），要么加速追赶，绝不能单方向拉长。
- 测试：vtest_idle_bridge 加 IdleBridge.stop() + process.exit(0)（K/L 段重新 start 后 rAF 桩会让 node 永不退出——这就是之前输出文件被锁的真因）。ui/script_sim/server_sim/settle_core 全绿。

## 第四批：修「打空气」（已推送 `c462940`，idle-bridge `20260905match4`）
- **用户实测**：击杀日志连发（⚔ 击败 ×6 同一分钟）但画面没怪 = 打空气；并伴随一次补发 5 场。
- **根因**：kill 判定（`t >= f.t1`）写在 mount（上场）**之前**。rAF 卡顿/切后台回来时 t 快进 → 每帧直接进击杀分支（settleKill + scriptIdx++），**怪从未 mount 就连续结算多场** → 击杀日志连发 + 画面空气。
- **修法（顺序铁律）**：上场衔接优先——`if (!showEnemy) { if (t < f.t0) 空场 return; mountShowEnemy(...) }` 放在 kill 判定之前，**先上台后判结束**，快进时每场至少"闪上台"再结算，杜绝无怪击杀。
- ⚠️ 测试进程等待的坑：`Wait-Process -Timeout` **不返回值**（$done 恒空）→ 误判 TIMEOUT 把完成进程也 Stop-Process。正确做法：轮询 `Get-Process -Id` 直到进程消失或超时。
- **现状**：演出/服务器对账链路已收敛（第三批时间轴同步 + 本批 mount 优先），剩余补发应只在切后台/节流等真异常时出现。

## 第五批：点击挂机秒开（已推送 `561b539`，idle-bridge `20260905match5` / main `match2`）
- **用户痛点**：点挂机后要等很久才开打。
- **根因**：start() 里先做一次"锚点 settle"（EF 冷启动 + settle 往返 + DB 多表读写）→ 返回后才 fetchMySession + buildNextScript → 才开打。EF 冷启动一次 1~4 秒全压在点击后。
- **关键发现**：`battle_session(start)` SQL 新建会话时 `last_settled_at = p_now`（= start 时刻）→ 前端 start 返回后直接 fetchMySession 拿 start 游标，其种子 = 服务器第一次 settle 的种子 → **锚点 settle 是纯空转，可完全省掉**（它 elapsed≈0 无收益，唯一作用是更新游标，而 start 已更新）。
- **修法**：抽 `bootstrapScript(curHp, seconds, retryMs)`（start 首段/settle 续段共用）；start 后直接 bootstrapScript（Pet.getCurHp=满血、默认 30s、失败 5s 首重试），不再 settleNow 锚点。点击→开打 = 一次 DB 查询 + 本地模拟（毫秒级）。
- **防双跑**：加 `bootstrapping` 锁——bootstrap 进行中 gaugeTick 的 `!script` 分支不另发 settle（否则 start 的 bootstrap 与 gaugeTick 触发的 settle 双跑，白打一次 EF）。
- **main.js**：点挂机先 addLog「⏳ 正在连接挂机服务器…」（EF 冷启动那段有反馈不干等）。
- 测试：idle_bridge/ui 全绿。EF 冷启动本身无法消除（空闲回收后首次调用必慢），但已压到"整个挂机生命周期仅 start 一次"。
