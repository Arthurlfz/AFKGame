## 追加1：神狐待机动画排障（承接 09-20 追加18/19；用户问"是不是要外部插件"）

### 结论一：不需要任何外部插件（已取证）
- `assets/pets/anim/god/血月神狐-idle.png` 是**标准静态 PNG**（签名 `89504E47`，只有 IHDR + 37×IDAT + IEND，

### 结论二：素材是**有动作的**，素材锅排除（我自己算的，不靠看图）
写了个临时脚本用 **Node 内置 zlib** 解 PNG 并逐帧统计（用完已删）：
拼接 IDAT → `zlib.inflateSync` → 逐行反算 filter（None/Sub/Up/Average/Paeth）→ RGBA 像素阵。
24 帧统计结果：
- **质心横向活动范围 54.17px（占 256px 帧宽 21%）**，纵向 9.03px

⇒ 这 24 帧不是"重绘了 24 遍"（对比 pack3-shadowrabbit 那批只有 <1.2px 位移），是**真动作**，
播放时肉眼应该能看出狐在左右摆动。**所以"静态/不动"不能用素材解释。**

### ⭐ 关键技术招数（记下来，以后"我这里好好的、用户那里没变"都用它）
**用 `fetch` 的两种 cache 模式把"浏览器缓存 vs 服务器真身"分开**：
```js
fetch(url, { cache: 'force-cache' })  // 直接吃本地缓存 —— 这就是用户页面上正在跑的那份
fetch(url, { cache: 'no-store' })     // 强制走网络 —— 这是磁盘上的真身
```
两者不一致 = **纯缓存问题，与代码对错无关**；两者一致且都旧 = 我这边文件没改到。
⚠️ 之前只用 `no-store` 抓，只能证明"服务器上是对的"，**完全测不出浏览器缓存**，白折腾一轮。
⚠️ 用 JS 生成的诊断页必须**跑在同一个地址前缀**（同源 + 同端口）才有意义，页面上要显示自己的 origin。

### 探针串的坑

## 追加2：🔴🔴🔴 真凶找到 —— 「减少动态效果」把游戏页所有 CSS 动画压成了静帧

用户回报诊断页①②两条结论：**① 动画在跑 ② 浏览器手上是新版（缓存排除）**。
⇒ 同代码、同浏览器、独立页面能跑 / 游戏页不动 ⇒ 差异**只剩"游戏页加载了十几个外部 CSS"**。

### 根因（game.css / design-tokens.css / market-cascade.css 两处各一条）
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration:.01ms !important;
    animation-iteration-count:1 !important;
  }
}
```
（`ui-fixes.css` 还有 `body.rm-anim *` 的同策略变体。）开了「减少动态效果」的机器上，
**游戏页所有 CSS animation 会在 0.01ms 内播完并停住 ⇒ 永远定格在第 1 帧**。
它是 `* {}` + `!important`，**任何针对性规则都盖不动**（想用更高 specificity 的 !important 去对轰 = 项目明令禁止的补丁式修复）。

⭐ **这类 bug 的特征（下次照着认）**：同一个浏览器里，**独立页面能跑、游戏页不动**；
且 "变量失效" 和 "动画被压"，症状**一模一样**（都是静帧、都不报错）。区分办法就是让诊断页**刻意加载游戏页那些 CSS**。

### 定案实现：播放彻底搬出 CSS，改 JS 定时器直驱 transform
`pet-sprites.js` 新增 `playFrames(strip, frames, dur, once)` / `stopFrames(strip)`：
- 每 `dur*1000/frames` ms 写一次 `strip.style.transform = translateX(-k × 容器宽 px)`
- **位移用像素**，不走任何百分比（同时把 09-20 那两条坑也一起免疫了）
- 元素被 `renderAll` 换掉后靠 `!strip.isConnected` **自动停表**，不留悬挂定时器
- `once`（attack）播完 `frames` 帧自己 clearInterval（顺带解决了"forwards 停在越界空白"那个死路径 bug）
- 容器宽每次现取（立绘是 `min(280px,46cqh)` 响应式），天然跟得上窗口变化
🔴 代价：**这套待机动作不再尊重 reduced-motion**（判断依据：它是宠物的核心表现内容，不是装饰动效）。已告知用户。

### 顺手修的第二个真 bug：重复挂载会重建节点
`mountAnimated` 现在幂等：**已经是同一只宠且还在播 → 原样 return true，不重建**。
原因：战斗页**每场 `resetBattle` / 每次 `renderAll`** 都会调用 `mountIcon` → 重建 `.pet-anim`
⇒ 播放进度每次归零 ⇒ 一轮 2.4 秒的动作永远播不完 ⇒ 玩家看到的就是"一直不动"。

### 顺带清掉：game.css 里的 `@keyframes pet-anim-play` 已删除（播放不再走 CSS）

### 守值（`vtest_pet_anim.js`，全绿）
不再有 `@keyframes pet-anim-play`｜不再拼 CSS animation 串（js 与内联副本两处）｜有 JS 播放器且挂载即起表
｜每帧位移按像素｜**重复挂载不重建节点**｜attack 走 `once=true`｜注释里必须留 `prefers-reduced-motion` 这个坑的说明
｜游戏.html 内联副本必须用 `this.playFrames(s, x.frames, x.dur`。
测试桩要补 `setInterval/clearInterval`（回非 0 句柄即可，`__frameTimer` 真值 = "在播"）。

`npm run check` = **86 通过 / 3 失败（存量红，无新红）**；`?v=`：game.css → `20260921anim3`。
诊断页 `anim-check.html` 已改成：加载 design-tokens + market-cascade 复现环境、**CSS 版 vs JS 版并排跑**、
显示 `matchMedia('(prefers-reduced-motion: reduce)')`。**验证完要删。**

## 追加9：🔴 `repack-sheet.js` 第一版把图写成横条纹（预览页一眼露馅）

用户回报「都不行啊」+ 截图：**B（重打包）显示成一片横条纹**。

### 根因：重采样缓冲区的内存布局和 PNG 的行优先布局不一致
写像素时用了"按帧分块"的索引 `((k*FH + Y)*FW + X)*4`，
而 `encodePNG` 把这块内存当成 `w = FW*N, h = FH` 的**逐行位图**读
⇒ 每帧被当成一整行塞进去 ⇒ 输出成横条纹。
修法：改成 `((Y*FW*N) + k*FW + X)*4`（第 Y 行 = 所有帧的第 Y 行拼起来）。

### 🔴 教训（更值钱的那条）：**自检只验"边缘透明"是抓不到这种错的**
第一版自检只算"每格左右边缘的实心占比"，而错位后的图**边缘恰好还是透明的** ⇒ 自检通过 ✅
⇒ 于是我把一个坏文件交给了用户看。
**修法**：自检加第二条 —— **逐帧不透明像素数 vs 源的 源×scale²**（最大偏差 ≤25% 才算过）。
现在两条自检 + 实测：`①边缘实心 33%→0% ②内容偏差 2.5%`。
⭐ **规矩：写生成类工具（图/音频/数据），自检必须验"内容对"，不能只验"边界条件对"。**
