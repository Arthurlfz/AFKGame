## 背包格子紧凑化（PoE 式 48px 固定网格）
- **根因**：背包格子大不是因为格子本身大，而是 `ui-bag.js` 硬编码 `BAG_COLS=6` + CSS `repeat(6, minmax(0,1fr))` 把格子拉到 95~145px。
- `game.css` `.bag-window .bag-item-grid`：`--bag-cell:48px` / `--bag-gap:2px` + `repeat(auto-fill, var(--bag-cell))`，`grid-auto-rows:var(--bag-cell)`，padding 10→6px；**删掉 `.bag-slot` 的 `aspect-ratio:1/1`**（与固定行高打架）；空格槽 45° 纹理改 `calc(var(--bag-cell)/8)` 跟随格子。
- 格内只留图标：`.nm` display:none（名称走已有 tooltip/详情面板）、`.ico` 26px/20px、`.corner` 9px 右下+黑描边+pointer-events:none、`.qmark` 15px。稀有度色边 / hover / dragging / bc-idtarget / bc-drop 全保留。
- **列数同步（关键坑）**：`ui-bag.js` 删 `BAG_COLS=6`，改为 `readRealCols(grid)`（`getComputedStyle(grid).gridTemplateColumns` 按空白 split 取段数；`clientWidth<=0` 或单段不采信——display:none 下 auto-fill 不解析）→ 先按容器宽估算铺槽位，再按真实列数最多重排一次；`ResizeObserver`（防抖 100ms）监听 gridArea，列数变化才整包 `renderBag()`。VM 桩环境（无 getComputedStyle/ResizeObserver/clientWidth）全部安全降级到回退 6 列。
- **死代码清理**：`ui-polish.css` 里 `.bag-grid.poe-grid{--cell:54px}` 与 `.pcol:nth-child(3) .poe-grid{--cell:46px}` 从未命中过（JS 生成的是 `.bag-item-grid.bag-grid-real`，且背包窗口没有三列 `.bag-wrap--tri`），已删并留指引注释。
- 版本号：`game.css?v=20260907bag48`、`ui-bag.js?v=20260907bag48`。vtest_bag 与全量 vtest 全绿。
