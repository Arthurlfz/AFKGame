## 背包窗口重开飞左上角（makeDraggable 定位模型 vs !important 打架，已修）
- **现象**：按过一次背包窗口标题栏（点一下就算）后，重开背包窗口整窗飞左上角，偶概率。
- **根因（三处打架）**：① `makeDraggable`（ui-common.js）mousedown 把 left/top 内联置 0、位置交给 translate3d，mouseup 不还原；② 关窗后内联 left:0/top:0 残留；③ 重开时 `ui-fixes.css` 的 `transform:translate(-50%,-50%) scale(1) !important` 把位移盖回居中，但内联 left:0/top:0 盖不掉（inline > 非 important）→ 窗口锚定原点再回拉半格 = 左上角。该 !important 还顺带废掉拖拽（translate3d 永远被盖）。
- **修法（统一 left/top 定位模型）**：① makeDraggable 改为 mousedown 时 `left=rect.left px; top=rect.top px; transform='none'`，移动直接改 left/top（rAF 节流），不再归零靠 transform；② openBagWindow 打开前清残留内联 left/top/transform（每次打开回 CSS 居中）；③ 删 ui-fixes.css 的 transform/transition !important 覆盖块（game.css 非 important 版本接管）；④ patchBagOpen 去掉内联 opacity/transform 强制，只留 is-open 兜底（后台 rAF 修复）。
- **铁律**：可拖拽窗口只用一种定位模型； symptoms 补丁（!important transform 强制）会反过来废掉拖拽和复开定位。ui-quest.js 694 注释早已点破此坑。涉及：ui-common.js / ui-bag.js / ui-fixes.js / ui-fixes.css，?v=20260911dragfix。vtest_ui/vtest_task12_ui 全绿。

### ✅✅ 装备 T 阶改 PoE 模式（用户否决"全 T1 确定函数"：「那打造系统白做了？我的意思是可以出现T1」+ 指路「去读 PoE / 火炬之光的词缀打造」）
- **PoE 规则核实**（PoE2 stratlore 指南 + PoE wiki 常识）：每个 tier 有自己的 **ilvl 门槛 + 生成权重**；掉落时把
  「门槛 ≤ 物品 ilvl」的 tier 全部进池**按权重抽** —— 高档 tier 进得了池但权重低。T1 最强、数字越小越强（常见误区）。
  稀有度约束的是前/后缀**槽位上限**（白 0、蓝 1+1、金 3+3）。iLvl 由区域/怪物等级决定，与角色等级无关。
- **落地**（config + equipment.js）：
  ① `affixIlvlGates = {1:70, 2:60, 3:25, 4:1, 5:1}`（每档门槛；**T5 门槛 1 必须在表里，否则权重分母少它、全部分布偏移** —— 踩过）；
  ② `affixTierWeights = {1:5, 2:15, 3:30, 4:25, 5:25}`（per-tier 权重，词缀与底材同池）；
  ③ `rollAffixTier(ilvl)`：池 = 门槛达标的 tier，按权重抽；**每条词缀独立 roll**（同件金装可 T1/T3 混排）；
  ④ 底材 = 同池 roll；⑤ 颜色/条数不变（affixCountByIlvl + rarityIdFromCount）。
- ⚠️ **两度做错被用户纠正**：第一版做成「稀有度决定 T 阶」（用户打脸 T1 最好却说成 T3 进阶）；第二版做成「达到门槛全 T1 的确定函数」（用户打脸「打造白做了」）。
  ⓘ **教训：做随机词缀系统前先读 PoE 的规则书，别自创「确定函数」** —— PoE 的 tier 池 + 权重是几十年打磨出来的答案，
  "解锁 = 进池"而非"解锁 = 必出"；权重表才是稀有度调节器。

### 审计第 2 批：宠物资产链（合成/涅槃/进化/培育）
- ⭐ **本批最重要的认知：RLS 只控「行归属」不控「列/值」**。查法 = `pg_policies`(qual/with_check) + `pg_constraint` + `pg_trigger`。本项目这些资产表**触发器为零**、`materials` **连一个 CHECK 都没有** → 登录玩家不改前端、一条 REST `PATCH /rest/v1/materials?user_id=eq.<自己> {"quantity":999999}` 就能造材料。有跨玩家交易时这是**偷别人资产**，不是自欺欺人。
- 🔴 **已修两张（能安全收口、不打断功能的）**：`supabase/migrate_asset_write_hardening.sql`

## 第 13 批：`idle-bridge.js` 三处（逐行读码后改，不再依赖子代理）

- 🟠 **1. `callFn` 裸 fetch 无超时 → 一次挂起锁死整个模块（已修）**：`settleNow` 用 `settling` **布尔锁**串行化，fetch 在"连接挂起"时可永远 pending → `settling` 永不释放 → 拿不到新剧本 + 兜底 `tick` 也被同一把锁挡 → **画面不动、控制台干净、零日志**。修：`AbortController` + 15s 超时，返回 `'TIMEOUT'`。

- 🟡 **3. `stopShow()` 不复位 `waitingHeal`、不收立绘（已修）**：`startShow` 清了 `waitingHeal` 但 `stopShow` 没清 → 停机后 `!showEnemy && !waitingHeal` 血量对齐分支永不成立（宠物血量对不上服务器真账）；`#enemy-fighter` 不隐藏 → 打怪中途停机留一只怪在画面上（`finishShowFight`/`enterHealWait` 都隐藏了，就 `stopShow` 漏）。
