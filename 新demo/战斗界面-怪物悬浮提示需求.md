# 战斗界面 · 敌方怪物悬浮提示 需求规范

> 写给前端 Agent 看的需求文档。拿到就能照着写，不用再问。
> 适用范围：`#enemy-icon` / `#enemy-icon-name` 鼠标悬停时弹出的怪物信息框。
> 数据来源：战斗模块 `state.enemy`（每场战斗开始时由 `scaleEnemyStats` 算好，挂在 `window.Battle` 上，前端可直接读）。

---

## 一、显示哪些字段（含要不要加那几个）

**结论：全部加上。** 基础属性 5 项 + 怪物类型 + 地图难度 + 掉落品质权重 + 经验值。

### 1. 基础属性组（每场战斗实时算出来的，必显示）

| 展示名 | 数据来源 | 说明 |
|--------|----------|------|
| 名称 | `enemy.name` | 直接显示，不用改 |
| 等级 | `enemy.level` | 显示成「Lv.X」 |
| 生命 | `enemy.hp` / `enemy.maxHp` | 显示成「当前值 / 上限值」，战斗中实时变 |
| 攻击 | `enemy.atk` | 直接显示整数 |
| 防御 | `enemy.def` | 直接显示整数 |
| 速度 | `enemy.spd` | 直接显示整数 |

> 命名全用大白话：「生命」不用「HP」，「攻击」不用「ATK」，「防御」不用「DEF」，「速度」不用「SPD」。

### 2. 怪物类型 —— 要加

- 来源：`enemy.enemyType`，值只有三种：`normal` / `evolved` / `mutant`。
- 显示文案：普通 / 进化 / 变异。
- **加的理由（玩家体验）**：玩家一眼能看出这怪值不值得打。变异怪掉金色装备概率最高（看下面掉落权重），是玩家挂机时最想偶遇的「好怪」，不标出来玩家根本分不清；进化怪次之。不显示类型，玩家就丢了「冲着好怪去刷」的动力。

### 3. 所属地图难度 —— 要加

- 来源：`enemy._diff`（地图难度系数，如 1.0 / 1.5 / 2.0），前端保留两位小数显示成「难度 ×X.XX」。
- **加的理由**：难度系数直接决定怪多硬、多痛。玩家换图后想确认「这图的怪是不是比上图强了一截」，给个系数让他心里有数，不用自己挨打试。属于低成本高信息量的字段，加上不亏。

### 4. 掉落品质权重（白 / 蓝 / 金）—— 要加

- 来源：`enemy.rarityWeights`，对象形如 `{ white: 80, blue: 18, gold: 2 }`，数值是百分比权重。
- 显示成一行三色小条或三色数字：「白 80% · 蓝 18% · 金 2%」，白/蓝/金用对应颜色字（白=灰、蓝=#4aa3ff、金=#ffb84a，跟游戏内稀有度配色一致）。
- **加的理由（重点）**：这是玩家最关心的「这怪掉好东西的概率」。游戏核心 G 点是「捡漏、追求稀有」，玩家选图、蹲怪本质就是在赌掉落。把权重直接亮出来，玩家能判断「这图金装概率 2% 还是 55%（变异怪）」，直接服务于交易/养成的核心循环。不加这一项，悬浮提示就失去了大半意义。

### 5. 经验值 —— 要加

- 来源：当前战斗**没有现成字段**，需要按下面公式算（策划定值，前端照算）：
  - `experience = round( (enemy.level × 5 + enemy.maxHp × 0.1) × enemy._diff )`
  - 例：Lv.10、生命约 200、难度 ×1.0 → `(10×5 + 200×0.1)×1.0` = `(50+20)` = **70 经验**。
  - 难度越高、怪越强，经验越多，玩家容易理解。
- 显示成「经验 +X」（胜利后这只怪给当前出战宠物加的量）。
- **加的理由**：经验是成长的硬通货，玩家挂机就是来升级的。让他悬停就能预估「打这只涨多少」，方便判断要不要在这图继续刷。公式简单、不新增任何后端字段（纯前端算），符合「只改配置/只在前端算」的规矩。

> 说明：怪本身没有「经验条/等级上限」概念，经验值是「怪奖励给玩家宠物」的量，所以放在「掉落信息」组里更顺（见下）。

## 二、排版规范

### 字段顺序（从上到下）

```
名称（标题，带怪物类型标签）
等级

—— 基础属性 ——
生命：当前 / 上限
攻击：X
防御：X
速度：X

—— 掉落信息 ——
怪物类型：普通 / 进化 / 变异
地图难度：×X.XX
掉落品质：白 XX% · 蓝 XX% · 金 XX%
经验：+X
```

### 分组

明确分两组，中间用一条细分隔线：

1. **基础属性**：生命、攻击、防御、速度（纯战斗数值）。
2. **掉落信息**：怪物类型、地图难度、掉落品质、经验（跟「打它图啥」相关）。

> 名称 + 等级放在最顶，作为标题区，不进分组。

### 命名与样式

- 全大白话，禁用英文缩写（HP/ATK/DEF/SPD/EXP 一律不出现）。
- 标签色用游戏内暗黑风配色（参考 `ui-battle.js` 现有 `--text-dim` 做标签、亮色做数值）。
- 掉落品质的白/蓝/金字用对应稀有度颜色，跟背包、掉落日志保持一致。
- 怪物类型标签用小色块：普通=灰、进化=蓝、变异=金（跟掉落品质呼应，玩家一看就懂档位）。

## 三、触发与交互

- **触发**：鼠标悬停（mouseenter）在 `#enemy-icon` 或 `#enemy-icon-name` 上 → 显示提示框；鼠标移开（mouseleave）→ 隐藏。
- **位置**：**固定位置**，不跟鼠标走。建议固定在敌方图标**右上方**（或右侧，避免被屏幕边缘裁掉，需要做边界翻转：靠近右边缘时翻到左侧）。理由：战斗是挂机自动进行的，鼠标可能不在怪身上，固定位置更稳定、不晃眼；跟随鼠标在自动战斗里反而容易闪。
- **实时刷新**：**要实时刷新**。战斗中怪掉血，`enemy.hp` 每 tick 在变，提示框里的「生命：当前 / 上限」要跟着 `updateBars` 同步更新（前端在 `updateBars` 里顺手刷新提示框内容即可）。其余字段（攻击/防御/速度/类型/难度/掉落/经验）本场不变，不用每帧重算。
- **提示框不要挡住血条和飘字**：固定在图标侧边，不盖住 `#enemy-hp-bar` 和飘字区域。

## 四、边界情况

1. **战斗未开始（没有怪 / 未选地图）**
   - 此时 `state.enemy` 为空，`#enemy-icon` 显示的是静态占位（如初始的「莱姆」）。
   - 悬停时：**不弹提示框**，或弹一个极简占位「未遭遇敌人」。建议直接不弹，避免误导（占位怪不是真怪，数值是假的）。
   - 前端判断：读 `state.enemy`，为空就 `return` 不显示。

2. **换场后（一场打完、下一只怪出现）**
   - `beginFight` 会重新算 `state.enemy` 并调 `resetBattle`。
   - 提示框内容**必须在换场时整体重算**：如果提示框正显示着，下一场开始时用新的 `state.enemy` 重新填充所有字段（类型/难度/掉落/经验都可能变）。
   - 前端做法：把「渲染提示框内容」抽成一个函数，在 `resetBattle` 和 `updateBars` 两处都调用（resetBattle 全量刷新，updateBars 只刷生命）。这样换场自动更新，不用额外挂监听。

3. **战斗中切换出战宠物**
   - 不影响敌方怪数据（`state.enemy` 不变），提示框无需变化。

4. **悬停时正好怪被打死 / 换场**
   - 若提示框显示中怪死了并进入下一场：按第 2 条，resetBattle 重算即可，提示框无缝切到新怪。

- [ ] 位置做边缘翻转，不盖血条和飘字。
- [ ] 配色沿用游戏现有暗黑风 + 稀有度三色（白灰/蓝 #4aa3ff/金 #ffb84a）。

## 附：为什么这些字段都该加（一句话总结）

基础属性帮玩家「打得过打不过」，怪物类型/地图难度/掉落品质/经验帮玩家「值不值得打」——后者正是这游戏「挂机捡漏、追求稀有」核心循环的命门，缺一个玩家就少一分刷图的动力。所以全加，且掉落品质权重必须亮出来。
